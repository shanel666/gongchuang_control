## ② 前置知识（零基础补 5 分钟）

- **STM32 工程是怎么跑起来的**：所有 `.c` 经 Keil 编译链接成一个 `Project.hex`，通过 FlyMcu 从串口烧进芯片。上电后执行 `Start\startup_stm32f10x_md.s` 启动汇编 → 配 72MHz 时钟 → 跳进 `User\main.c` 的 `main()`。
- **标准外设库（STDPeriph）**：ST 厂商给的驱动函数库，`Library\` 里那一堆 `stm32f10x_gpio.c`、`stm32f10x_usart.c` 等，封装了寄存器操作（`GPIO_SetBits`、`USART_SendData` 这些函数都是它提供的）。**只调用，不阅读**。
- **中断**：硬件事件（如串口收到一个字节）可以打断 `main()` 正在执行的代码，自动跳去执行固定名字的函数（如 `USART1_IRQHandler`），执行完再回来。
- **Keil 工程分组**：`Project.uvprojx` 里定义了 7 个逻辑分组（Start / Library / System / Hardware / User / mingling / app），与目录一一对应；磁盘上的文件必须同时被加进分组才会参与编译。

## ④ 逐区讲解

### 4.1 A 类：模板与库（占 90% 代码量，0% 阅读优先级）

| 文件 | 作用 | 为什么不用读 |
|---|---|---|
| `Start\startup_stm32f10x_md.s` | 上电向量表、中断入口 | 全汇编，C8 芯片对应 md（中等容量），固定不变 |
| `Start\core_cm3.*` | Cortex-M3 内核函数 | ARM 提供 |
| `Start\system_stm32f10x.c` | 把主频配成 72MHz | 只需要知道 `SYSCLK_FREQ_72MHz` 生效即可 |
| `Start\stm32f10x.h` | 全部寄存器/引脚定义 | 当字典用 |
| `Library\stm32f10x_*.c` | GPIO/USART/RCC/… 标准库驱动 | 23 个外设的 `.c` 全在工程里，但实际只用到 GPIO、USART、RCC、misc |
| `System\Delay.c` | `Delay_us/ms/s` 阻塞延时 | 41 行，会用就行 |
| `User\stm32f10x_it.c` | 异常处理（HardFault 等） | **重要例外**：它里面的中断函数是空壳，真正的串口中断写在 `Serial.c` 里（链接器靠函数名定位，同一个中断函数名整个工程只能有一个） |

### 4.2 B 类：教程风格外设驱动（江协 STM32 教程风格）

这类文件的命名、注释格式、函数结构（`XXX_Init` / `XXX_ShowNum`）都来自 B 站江协科技 STM32 入门教程，大概率是建工程时拷来的，**只需要知道引脚分配和提供的函数**：

- `OLED.c`：软件模拟 I2C（不用硬件 I2C 外设），`OLED_ShowString/ShowNum/ShowSignedNum(行,列,值)`。**引脚已被学长改过**（教程原版是 PA0/PA1，现在是 PB15/PB14），从机地址 0x78。
- `Key.c`：`Key_GetNum()` 返回 1/2/3，阻塞式（按住不放会卡在校抖 while 里）。引脚 PB1、PB11、PB10。
- `LED.c`：`LED1_ON/OFF/Turn`（PA1）、LED2（PA2）、PC13 板载灯。
- `Serial.c` 的**前半段**（`Serial_Init`/`Serial_SendByte` 等，1~230 行）是教程模板的 USART1 基础部分；后半段（USART2/3、电机帧解析、陀螺仪喂入）是 C 类。

### 4.3 C 类：学长业务代码（后续所有步骤的主角）

| 文件 | 一句话职责 | 哪一步细讲 |
|---|---|---|
| `User\main.c` | 初始化 + 当前生效的 PA8 按键闭环转 90° 测试 + 死代码里的自动路线 switch | 04、05 |
| `app\motor.c` | 组装所有电机指令帧：`qianjin_/houtui_/zuo_/you_/shun_yaw_/ni_yaw_`、`motor_enable_all`、`motor_read_pos/set_pos`、`motor_rotate_speed` | 02、03、08 |
| `app\path_planner.c` | 网格建图、Dijkstra 求最短路、提取拐弯点 | 07 |
| `app\path_config.h` | 起终点、障碍坐标、初始朝向的宏（改场地参数只改这里） | 07、09 |
| `Hardware\Gyro.c` | 逐字节解析 JY901 的 `55 53` 角度帧，输出 Z 轴 yaw（0.01°） | 04 |
| `Hardware\Serial.c`（C 类部分） | USART1 中断解析电机回包；USART2 中断同时解析陀螺仪帧和 `k:数字`；USART3 自研 Printf 输出角度 | 06 |
| `mingling\mingling.h` | 历史文物：最早期手工写死的 13/52 字节指令数组（速度 2000、脉冲 10000） | 本文 4.4 |

### 4.4 为什么 mingling 是废弃的（30 秒历史）

最早每个动作的 4 个电机指令都是手写死的数组（`qianjin1[]`…`qianjin4[]`，见 `mingling.h`）。后来学长把它改成 `motor.c` 里的**动态组帧函数**：距离参数 → 现算脉冲数 → 只填变化的字节（地址、方向、脉冲）。`mingling.c` 现在只剩 4 行 include，工程里**没有任何地方引用它**（在 Keil 里仍然编译，但无实际作用）。

### 4.5 硬件地图（从代码反推，引脚全部核实过）

| 硬件 | 接到单片机 | 波特率/参数 | 代码位置 |
|---|---|---|---|
| 4× 张大头 ZDT-X42S 闭环步进（麦轮 FL/FR/RL/RR） | **USART1**：PA9(TX) / PA10(RX)，一条总线 4 个从机，地址 1~4 | 115200, 8N1 | `app\motor.c`、`Serial.c` USART1 |
| JY901 兼容陀螺仪 | **USART2**：PA3(RX) 接陀螺仪 TX | 115200, 8N1 | `Hardware\Gyro.c`、`Serial.c` USART2 |
| 电脑 USB-TTL 调试（`k:数字` 指令） | 与陀螺仪共用 USART2：PA2/PA3 | 115200 | `Serial.c` USART2_IRQHandler |
| 角度文本输出（上位机/下位机，待确认） | **USART3**：PB10(TX)（只发不收） | 115200 | `Serial.c` USART3 |
| 0.96" OLED | 软件 I2C：**PB15=SCL、PB14=SDA**，从机 0x78 | — | `Hardware\OLED.c` |
| 3 个按键 | **PB1 / PB11 / PB10**（PB10 与 USART3 冲突，第 3 键不可用） | — | `Hardware\Key.c` |
| 临时测试按键 | **PA8**（低电平按下） | — | `User\main.c` 主循环 |
| LED | PA1（LED1）、PA2（LED2，冲突不可用）、PC13（板载） | — | `Hardware\LED.c` |

> 已知的引脚冲突（后面会反复遇到）：**PA2 = USART2_TX = LED2**；**PB10 = USART3_TX = 按键3**。初始化顺序决定谁生效，所以这两个外设目前当不存在。

### 4.6 高频改动速查表（需求 → 文件）

| 我要改… | 去哪个文件 |
|---|---|
| 前进/旋转的速度、加速度、脉冲标定 | `app\motor.c` 顶部 4 个宏 |
| 动作本身（发什么帧、几个轮子转） | `app\motor.c` 对应函数 |
| 路线顺序、上电干什么 | `User\main.c`（`main()` 与 switch 步骤） |
| 起点/终点/障碍/初始朝向 | `app\path_config.h` |
| 寻路算法（网格、权重、连边） | `app\path_planner.c` |
| 屏幕上显示什么 | `User\main.c` 里的 `OLED_ShowXxx` 调用；驱动函数本身在 `Hardware\OLED.c` |
| 陀螺仪解析/安装方向换算 | `Hardware\Gyro.c` |
| 串口接线、波特率、新增一个串口 | `Hardware\Serial.c` |

## ⑤ 动手验证

1. **对照 Keil 分组**：用 Keil 打开 `Project.uvprojx`，左侧 Project 面板正好 7 个分组，与本文目录树一一对应；点开 `app` 看到 5 个文件，点开 `User` 看到 4 个。
2. **编译一遍**（不接硬件也行）：
   - **Keil5**：打开 `Project.uvprojx` → F7 构建，应能看到 `Objects\Project.hex` 生成（`Objects\` 已被 gitignore）；
   - **VSCode（本队首选）**：安装 **Embedded IDE（EIDE）** 或 **Keil Assistant** 插件，直接导入本 `.uvprojx`，底层复用 Keil 自带的 ARMCC（AC5）编译器，无需另装 GCC；再装 **C/C++（或 clangd）** 插件做跳转/补全。烧录仍可用 FlyMcu（ISP），有 ST-Link 也可配 cortex-debug。
   - 只是浏览代码、不编译：VSCode 直接打开文件夹即可，把 `Start\`、`Library\`、`System\`、`Hardware\`、`User\`、`app\` 加入包含路径后跳转才完整。
3. **验证中断位置**：全工程搜索 `USART1_IRQHandler`，结果只在 `Hardware\Serial.c`（`User\stm32f10x_it.c` 里没有）——记住这个反直觉点。
4. **验证文件历史**：在项目根目录执行下面命令，看 `motor.c` 是怎么一步步长大的：
   ```bash
   git log --oneline -- app/motor.c
   ```
5. **认清 C 类代码的总规模**：核心业务代码其实只有 7 个文件 ≈ 1700 行（main 394 + motor 293 + Serial 587 + Gyro 112 + path_planner 197 + 两个头文件），其余都是模板——**这个项目没有你想象的大**。
