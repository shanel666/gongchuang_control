## 四、逐行讲解

### 4.1 先看整体：三层调用关系

```
路线层（当前死代码）   switch(step)：case 0~9，每步只说"去哪个坐标"
      │  go_to(&cur_x, &cur_y, 目标x, 目标y)
      ▼
调度层   go_to()
      │  ① path_plan(起点,终点) → 关键点数组 xpath[]/ypath[]   ← 07 篇
      │  ② 逐段调 translation(相邻关键点)
      ▼
动作编排层  translation(x0,y0,x1,y1)
      │  朝向状态机 dir：朝向不对就先 shun/ni 转 90°，再 qianjin/houtui 平移
      ▼
动作层   motor.c：qianjin_/houtui_/shun_yaw_/ni_yaw_（组帧 + 同步帧）
      │
      ▼  每个动作后
到位确认 judge()：依次向 4 个电机发 0x3A，回包状态=0x03 才算这一段结束
      │
      ▼
驱动层   Serial.c：USART1 收发（06 篇细讲）
```

记忆要点：**switch 只管"去哪"，go_to 管"分几段"，translation 管"先转还是先走"，motor.c 管"发什么字节"，judge 管"走完没"。**


所以现在的固件**既不会走路线，也不会初始化障碍和使能**。这不是 bug，是学长调试时把测试循环留在了前面——但接手时必须知道。

### 4.4 judge()：一段动作怎么算完（main.c:23-76）

02 篇已经讲过状态字节 0x03，这里看它的**轮询结构**：

```c
while(1){
    查电机1（没到位才查）：清缓冲 → 发 01 3A 6B → 最多等 50ms → 回包[addr=01][3A][03]则 judge1=1
    Delay_ms(5);
    查电机2（同样流程）
    Delay_ms(5);
    查电机3
    Delay_ms(5);
    查电机4
    Delay_ms(5);
    四个都到位 → return 1;
    OLED 显示轮询计数;
    if(++guard > 60000) return 0;   // 兜底
}
```

- 已到位的电机不再重复查（judgeX 标志），只继续等没到位的；
- 每轮查一个电机前先清缓冲、清零接收数组，再比对地址+功能码+状态三重匹配（防串包）；
- `guard` 兜底：一轮最坏约 200ms（4×5ms + 4×50ms 等待），60000 轮约 **3 小时**——实际等于"几乎不超时"，只在电机死机/掉线时才会触发，注释也这么写。

### 4.5 translation()：朝向状态机（main.c:78-111）

`translation(x0,y0,x1,y1)` 只接受**同一行或同一列**的两个点（x 相同或 y 相同），否则 `return 0`。斜着走由上层 go_to 拆成多段，不会传到这里。

朝向用静态变量 `dir` 表示车头当前指向（网格坐标：左下原点）：

| dir | 朝向 | 坐标含义 |
|---|---|---|
| 1 | 北 | y 增大方向 |
| 2 | 西 | x 减小方向 |
| 3 | 南 | y 减小方向 |
| 4 | 东 | x 增大方向 |

四个分支结构相同，以"向北（y1>y0）"为例：

```c
if(dir == 2){ shun_yaw_(90); Delay_ms(1000); if(!judge()) return 0; dir = 1; }  // 朝西→顺时针转90
if(dir == 4){ ni_yaw_(90);   Delay_ms(1000); if(!judge()) return 0; dir = 1; }  // 朝东→逆时针转90
if(dir == 3) houtui_(distance);   // 朝南：不转身，直接倒车过去
else         qianjin_(distance);  // 已朝北：前进
return judge();
```

三个设计要点：

1. **只转 90°，不转 180°**：车头朝反方向（180°）时不转身，直接 `houtui_` 倒车。这是刻意的——麦轮原地转 180° 要两次 90°、误差更大，短距离倒车更省事；
2. **先转完才更新 dir**：`judge()` 成功后才 `dir = 新朝向`；失败直接 `return 0`，dir 保持原值（车没转过去，朝向记录也不能变）；
3. **转向后固定 Delay_ms(1000) 再 judge，平动后直接 judge**——两者不一致（见问题 N21）。

全部八个转向的 shun/ni 用法（按命名语义）：

| 转向 | 用的函数 | 按地理方位是否"名副其实" |
|---|---|---|
| 西→北、南→西、东→南 | shun_yaw | 顺时针 90°，名实相符 |
| 东→北、北→西、南→东、西→南 | ni_yaw | 逆时针 90°，名实相符 |

即：**在这张状态机里，shun/ni 是按"地理顺/逆时针"的名字语义写的**。03/04 篇曾发现函数名与物理方向推导相反（N8/N16），**2026-10-16 现场查明根因是电机反装（N24），地址对调后顺逆现象正确，这 8 处无需翻转，代码按现场版本保留**。

### 4.6 go_to()：一次"去某个坐标"的完整流程（main.c:210-227）

```c
static u8 go_to(u16 *cx, u16 *cy, u16 tx, u16 ty)
{
    u16 xpath[25], ypath[25];
    if(*cx == tx && *cy == ty) return 1;        // 已在目标，直接成功
    path_plan(*cx, *cy, tx, ty, 25, xpath, ypath);  // 黑盒：规划关键点
    if(key_point_num < 2) return 0;             // 无路径/被障碍封死
    for(i = 1; i < key_point_num; i++)
        if(!translation(xpath[i-1], ypath[i-1], xpath[i], ypath[i])) return 0;  // 逐段走
    *cx = tx; *cy = ty;                         // 指针回写当前位置
    return 1;
}
```

- 当前坐标用**指针**传进来（`&cur_x`），走完后由 go_to 更新，switch 不用自己管位置；
- 关键点含起点终点，所以从 `i=1` 开始逐段（第 1 段是 xpath[0]→xpath[1]）；
- 任何一段失败（judge 超时、不在同一行列）立即返回 0，**不会更新当前位置**——位置记录停在最后一个成功的关键点。

### 4.7 路线 switch：一个"步进状态机"（main.c:363-393）

```c
while(1){
    OLED 显示 step 和 yaw;
    switch(step){
        case 0: go_to(…目标点0…); 成功 step=1，失败 step=99;
        case 1: ...
        ...
        case 9: go_to(终点); 成功 step=100;
        case 100: OLED "PATH DONE"; while(1){}   // 完成：原地停
        case 99:  OLED "PATH ERROR"; while(1){}  // 失败：原地停
    }
}
```

规则极其简单：**每个 case 只有一个 go_to，成功就把 step 加 1，失败统一跳到 99。** case 里的点序列（起点 PATH_START=(2250,2250)，终点 PATH_TARGET=(2250,2250)）：

| case | 目标坐标 | 备注 |
|---|---|---|
| 0 | (2250,1200) | 向南 |
| 1 | (1200,2250) | 对角，规划绕行 |
| 2 | (1200,150) | 向南贯穿 |
| 3 | (150,1200) | 对角绕行 |
| 4 | (1200,2250) | 与 case 1 终点相同 |
| 5 | (1200,150) | **与 case 2 完全重复** |
| 6 | (150,1200) | **与 case 3 完全重复** |
| 7 | (2250,2250) = PATH_TARGET | 回终点，成功后 step=100 |
| 8 | (1200,150) | **永远不执行**（case 7 已跳 100） |
| 9 | (2250,2250) | **永远不执行** |

这显然是绕场测试路线，不是比赛 8 阶段（P0 待问）。两个小问题：

- **case 8、9 不可达**：case 7 成功直接 `step=100`，switch 里没有任何地方再把 step 设成 8/9（N22）；
- case 7 行尾注释写的是 `/* -> (1200,2250) */`，实际目标是 PATH_TARGET=(2250,2250)，注释抄错（N22）。

### 4.8 path_plan 接口（黑盒，07 篇打开）

```
输入：起点(x0,y0)、终点(x1,y1)、容量 n、两个输出数组
输出：key_point_num（关键点个数，0=无路径），xpath/ypath 存起点→终点的关键拐点
```

go_to 不关心 Dijkstra 怎么算，只消费这串坐标。`path_planner_init()` 负责把 4 个默认障碍填进 `obstacle[25]`（07 篇细讲）。

## 五、动手验证

1. **单步验证死代码**（Keil 仿真器或 VSCode + JLink）：在 298 行 `shun_yaw_(90)` 和 375 行 `case 0` 打断点，全速运行，断点永远不触发——直观确认"第一个 while(1) 之后全是死代码"。
