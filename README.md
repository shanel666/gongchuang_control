# 四麦轮小车（工程创新比赛）— STM32F103C8T6

> 本工程：基于 STM32F103C8T6 的四轮麦克纳姆轮小车，4 个「张大头」闭环步进电机驱动，
> 在 2.25 m × 2.25 m 网格场地上自动规划路径、避开障碍物，从起点走到终点。
> 当前主程序上电后自动依次经过指定坐标，完成路线后停机显示状态。

## 3. 两个串口的分工（重要！）

工程里有两个串口，**用途完全不同，接错线就“没反应”**：

| 串口 | 引脚 | 接什么 | 用途 |
|---|---|---|---|
| **USART1** | PA9(TX) / PA10(RX) | 电机总线 | 发运动指令、读位置 |
| **USART2** | PA2(TX) / PA3(RX) | JY901 兼容陀螺仪（可选 USB-TTL 调试） | 115200、8N1；接收并校验 0x55 0x53 角度帧，同时保留 `k:数字` 调试命令 |
| **USART3** | **PB10(TX)** / PB11(RX)（默认映射） | 上位机 USB-TTL / 无线串口模块 | 115200、8N1；输出调试文本；`DEBUG_MODE_WIRELESS` 下接收上位机命令 |

- 陀螺仪 TX 接 **PA3（USART2_RX）**，陀螺仪 RX 可接 **PA2（USART2_TX）**，并与单片机共地，波特率 **115200**、8N1。
- 上位机 USB-TTL 的 RX 接 **PB10（USART3_TX）**，GND 共地；打开串口工具选择这个 USB-TTL 对应的 COM 口。
- USART2 的电脑串口助手仍可接 PA2/PA3 做 `k:数字` 调试；USART3 输出调试文本。
- USART3 现在**收发都用**（RX 中断按行解析，给无线串口用）；PB10/PB11 和按键复用，
  接无线模块后 PB10/PB11 两个按键不要再按。
- 电机的 4 个从机都挂在 **USART1** 一条总线上，地址 1~4。

### 3.1 陀螺仪角度读取

`Hardware/Gyro.c` 在 USART2 接收中断中逐字节解析 JY901/WitMotion 兼容协议。只有帧头为 `55 53` 且第 11 字节校验和正确时，才更新 Z 轴（Yaw）数据。当前 `main` 中的临时测试循环每 200 ms 通过 USART3 输出一次最新角度，例如 `-12.34`：

- `Gyro_GetYawRaw()`：返回有符号 16 位原始值；
- `Gyro_GetYawCentiDegrees()`：返回百分之一度，换算关系为 `raw × 18000 / 32768`；
- USART3 输出格式为 `正负号/整数部分.两位小数\r\n`，单位为度，输出频率 5 Hz；
- 主程序把最近一次有效角度显示在 OLED 第 4 行，未收到有效帧时不会误报数据。

## 4. 电机通信协议

### 4.1 运动帧（13 字节）

```
[地址][0xFD][方向][速度H][速度L][加速度][脉冲B3][脉冲B2][脉冲B1][脉冲B0][模式][同步][0x6B]
```

| 偏移 | 含义 | 说明 |
|---|---|---|
| [0] | 地址 | FL=0x01, FR=0x02, RL=0x03, RR=0x04 |
| [1] | 命令 | 0xFD |
| [2] | 方向 | 0x00 正转 / 0x01 反转 |
| [3..4] | 速度 | 大端 2 字节 |
| [5] | 加速度 | 1 字节 |
| [6..9] | 脉冲数 | 大端 4 字节 |
| [10] | 模式 | 0x00 相对 / 0x01 绝对位置 |
| [11] | 同步 | 0x00 立即执行 / 0x01 等同步帧 |
| [12] | 校验 | 固定 0x6B |

### 4.2 速度模式（F6）与新增底盘模块

F6 是「持续速度」命令（不带走位回包）。本工程在 `app/chassis.c` 里新增了一套速度模式底盘逻辑，
帧格式在 `app/chassis_config.h` 里一行切换：

| 宏 | 帧格式（每帧 8 / 9 字节） |
|---|---|
| `CHASSIS_FRAME_LAYOUT_8B`（默认） | `[地址][F6][方向][速度H][速度L][加速度][同步][6B]` |
| `CHASSIS_FRAME_LAYOUT_9B` | `[地址][F6][方向][加速度H][加速度L][速度H][速度L][同步][6B]` |

默认用 8 字节：你给的示例 `01 F6 00 00 32 32 01 6B` 按它解析正好是速度 50（5.0 RPM）、
加速度 50、同步 1。如果手册明确写「加速度 0000-FFFF」（2 字节），把宏改成
`CHASSIS_FRAME_LAYOUT_9B` 即可，chassis.c 的组帧/发送代码不用动。

- 方向 `0x00=CW`、`0x01=CCW`；速度单位 **0.1 RPM**（`0x7E30` = 3000.0 RPM）；
  加速度单位 RPM/s（8 字节帧只有 1 字节，超过 255 会限幅）；
- 同步 `0x01` = 等 `00 FF 66 6B` 释放帧后四轮一起起步，`0x00` = 立即执行（默认 0，和旧代码一致）；
- 帧尾校验固定 `0x6B`。

> 旧版 `motor.c` 的 `motor_rotate_speed()` 也是 8 字节 F6，但速度单位没有统一；
> 新代码统一走 `chassis.c` 的 0.1 RPM，旧函数保留给旧的转向测试用。

### 4.3 新增：速度模式底盘（`app/chassis.c`）

| 文件 | 作用 |
|---|---|
| `app/chassis_config.h` | ★ 所有可调参数：帧格式、默认速度/加速度、标定、方向表、时序、时间修正 |
| `app/chassis.c` | F6 组帧 + 四个轮子方向表 + 梯形速度曲线定时停车 |
| `app/chassis.h` | 对外接口 |

```c
Chassis_Init();              /* 使能 4 个电机（上电默认失能） */
Chassis_Move(1000);          /* 前进 1000 mm，>0 前进 / <0 后退 */
Chassis_Strafe(-250);        /* 右平移 250 mm，>0 左移 / <0 右移 */
Chassis_Rotate(90);          /* 逆时针 90°，>0 逆时针 / <0 顺时针 */
Chassis_MoveAt(500, 150);    /* 15.0 RPM 前进 500 mm */
Chassis_Stop();              /* 按当前加速度减速停车 */

int32_t sp[4] = {300, -300, 1232, -30000};  /* FL/FR/RL/RR，0.1 RPM，带符号 */
Chassis_SetWheelSpeed(sp);   /* 连续速度：遥控/上层自己解算时用 */
```

- 方向表在 `chassis_config.h` 的 `CHASSIS_DIR_*`，和 4.5 的实测表一致；
  整轴反了改 `motor.h` 的 `MOTOR_FLIP_FWD/LAT/YAW_SWAP`，单轮反了改 `MOTOR_DIR_INV_1..4`；
- 速度模式没有位置回包，距离用**时间**近似：总时间 = 匀速时间 + 加减速补偿
  （梯形曲线；距离太短自动按三角形算），到点发 0 速度停车，
  再等 `max(CHASSIS_STOP_SETTLE_MS, 减速时间)` 让车停稳；
- 现场校正：命令 1000 mm，量实际距离，走多了调小 `CHASSIS_TIME_GAIN_PCT`，走少了调大；
- 时间换算依赖 `CHASSIS_PULSES_PER_REV`（驱动器细分，默认 3200）和 4.5 节下面的标定；
- 默认速度 30.0 RPM ≈ 123 mm/s，旋转 40.0 RPM ≈ 45 °/s（按当前标定）；
- 运动中按 PA8 可停车（`Chassis_SetAbortCheck()` 装回调，自检模式已经接好）。

### 4.4 其它帧

- **同步释放帧** `00 FF 66 6B`：直行时 4 电机都设 sync=0x01，最后发这帧让它们**同时起步**。
- **使能帧** `[addr] F3 AB 01 00 6B`：上电默认失能，运动前 `motor_enable_all()` 依次使能。
- **读位置** `[addr] 36 6B` → 回 8 字节 `[addr] 36 [dir] [pos×4] 6B`。

### 4.5 麦轮方向表（2026-10-23 换电机后实测标定）

这四个轮子的滚子朝向是"同手"的（不是常规左右镜像），所以映射和教科书不同：
**前进是"对角轮一组"，平移是"前后一组"，四个轮子同向才是旋转**。
下表是实际发出去的方向位（0x00 / 0x01），`MOTOR_DIR_INV_*` 目前全 0：

| 动作 | FL(1) | FR(2) | RL(3) | RR(4) |
|---|---|---|---|---|
| 前进 `qianjin_` | 1 | 0 | 0 | 1 |
| 后退 `houtui_` | 0 | 1 | 1 | 0 |
| 左平移 `zuo_` | 1 | 1 | 0 | 0 |
| 右平移 `you_` | 0 | 0 | 1 | 1 |
| 左旋 `ni_yaw_` | 1 | 1 | 1 | 1 |
| 右旋 `shun_yaw_` | 0 | 0 | 0 | 0 |

> 现场微调三个开关（都在 `app/motor.h`，改一个数、重编译即可，不用动上面的表）：
> `MOTOR_FLIP_FWD=1u`（前后轴整体反了）、`MOTOR_FLIP_LAT=1u`（左右轴整体反了）、
> `MOTOR_YAW_SWAP=1u`（旋转整体反了）。

> - 旧版"平移 = 四轮同向"其实是转圈，已按实测改掉；
> - "左右一组"（FL 1 / FR 0 / RL 1 / RR 0）会让四个轮子互相抵消，车原地不动，别用；
> - 旋转顺时针/逆时针哪个是哪个、以及左平移/右平移是否互换，用 P2/P3 现场确认，
>   反了只需改 `MOTOR_YAW_SWAP` 或把 `zuo_()/you_()` 两张表对调。

## 6. 路径规划

- **5×5 网格**，25 个交点，坐标单位 mm：

| | col0 | col1 | col2 | col3 | col4 |
|---|---|---|---|---|---|
| **x** | 150 | 675 | 1200 | 1725 | 2250 |
| **y** | 2250 | 1725 | 1200 | 625 | 150 |

- 障碍在 `app/path_config.h` 配置，`PATH_OBSTACLE_0..3` 默认是 4 个交叉口：
  `(675,1725)(1725,1725)(675,625)(1725,625)`。
- `path_plan(起点, 终点, ...)` 用 **Dijkstra** 算最短路，再提取「起点 + 拐弯点 + 终点」作为关键点，
  结果存 `xpath[]/ypath[]`，个数在全局 `key_point_num`。
- 附 `PATH_PLANNER_DEMO` 宏，可在 PC 上 `gcc -DPATH_PLANNER_DEMO path_planner.c` 单独验证算法。

## 7. 主程序流程

### 7.1 当前默认：全图路线状态机（`DEBUG_MODE_ROUTE`）

上电 → 初始化（LED/舵机/OLED/按键/USART1-3/陀螺仪）→ `motor_enable_all()` →
OLED 显示起点 → **3 秒倒计时**（此时摆车）→ 进入 `route_run()` 的 `while(1)`。

**状态就是"第几段"**：`step = 1..8`，OLED 第 1 行显示 `CASE n/8`。每跑完一段 `step++`，
最后 `step = 99`（`PATH DONE`）；失败 `98`（`PATH ERROR`），按 PA8 中止 `97`（`ABORT BY PA8`）。

```c
while(1){
    /* 顶栏显示 CASE n/8，4 行 AT 当前坐标；TO 由 leg_goto() 进来时画 */
    switch(step){
        case 1: step = leg_goto(2250u, 1200u) ? 2u : (abort_flag ? 97u : 98u); break;  /* → E 堆码 */
        case 2: step = leg_goto(1200u, 2250u) ? 3u : (abort_flag ? 97u : 98u); break;  /* → B 原料 */
        ...
        case 8: step = leg_goto(2250u, 2250u) ? 99u : (abort_flag ? 97u : 98u); break; /* → 回到起点 */
        case 99: /* PATH DONE */   case 98: /* PATH ERROR */   case 97: /* ABORT */
    }
}
```

**每个 case 就是"去哪个点"**，目标坐标直接写在 case 里；到了就把 `step` 换成下一个。
`leg_goto(tx, ty)` 内部：`path_plan()` 拆成直角小段 → 每小段先 `leg_face()` 对准朝向
→ `qianjin_/houtui_` 走完 → `wait_motors()`（有界等待，驱动器掉线不会卡死）。
它一进来就把 `TO x,y` 画到第 3 行；走完更新 `fsm_x/fsm_y`，第 4 行 `AT` 跟着变。

**陀螺仪闭环转向**（`gyro_turn_to_abs`，**绝对角度**）：

1. 开机倒计时结束时记一次零点 `yaw_zero`，之后 北=0°、西=+90°、南=180°、东=-90°；
   每次转向都是"转到某个绝对角度"，所以多段之间**不会累积偏差**；
2. 误差 = 目标绝对角 − 当前绝对角；**按误差直接算脉冲，一步到位**：
   `脉冲 = |误差| / 36000 × MOTOR_PULSE_PER_360DEG`（例：误差 10° → 17208/360×10 = 478 脉冲）；
   不再按比例一点点逼近；
3. 每次发完 `wait_motors()` → `gyro_turn_settle()`（等车体停稳：100 ms 间隔两次角度差 < 0.5°）
   再读一次全局角度重算误差，最多补 **15** 次（误差按 `1−k` 衰减，标定差一半约 10 次收敛）；
4. 误差 ≤ 0.1° 算到位；补差用尽后残留 ≤1° 也接受。

> 中间踩过的坑：① 把 `err`（0.01°）当"度"直接发给 `ni_yaw_` → 每次被限幅成 30° → 必然超调；
> ② 电机报"到位"时车体还在晃，立刻测角度会反复过冲。两个问题都已修掉。

其它：任何阶段按 **PA8** 中止；陀螺仪没数据时转向退化为开环 90°（第 2 行显示 `NO GYRO`），
`PATH ERROR` 会停在原地不会带着错朝向继续跑。

路线（起点 `PATH_START_X/Y = (2250,2250)`，即场地图的 A=起点1）：

| 段 | 目标 | 场地点 |
|---|---|---|
| 1 | (2250,1200) | E 堆码 |
| 2 | (1200,2250) | B 原料 |
| 3 | (1200,150)  | C 粗加工 |
| 4 | (150,1200)  | D 暂存 |
| 5 | (1200,2250) | B |
| 6 | (1200,150)  | C |
| 7 | (150,1200)  | D |
| 8 | (2250,2250) | A 终点（回到起点） |

> - 每个 case 就是一次 `leg_goto(x, y)`，增删站点直接改 `main.c` 里那一行；
> - 起点坐标和初始朝向在 `app/path_config.h`（`PATH_START_*`、`PATH_INITIAL_DIR`）；
> - `PATH_INITIAL_DIR=1`（朝北）时第一段会**倒车** 1050 mm；若上电时把车头朝**南**摆，
>   把 `PATH_INITIAL_DIR` 改成 `3`，第一段就是正着前进；
> - 用"完美闭环"离线推演过整条路线：8 段 13 个动作，最终精确回到 `(2250,2250)`。

### 7.2 闭环旋转单独测试（`DEBUG_MODE_TURN`）

不跑路线，只测 `gyro_turn_to_abs()` 这一个函数——它就是路线里用的同一份闭环转向实现。
目标角度是**绝对角度**（开机时车头方向记为 0°）。

| 按键 | 动作 |
|---|---|
| **PA12** | 目标角度 +90° 后转过去 |
| **PA11** | 目标角度 −90° 后转过去 |
| **PA8** | 不改目标，原地重新对准当前目标（**用手把车扳歪再按一下，看它能不能回正**） |

每次转完把过程量留在屏幕上：

| 行 | 内容 |
|---|---|
| 1 | `ABS+090 C2`：绝对目标角、补差次数 |
| 2 | 左半是 `judge` 查询计数，右侧 `Y±ddd` 是当前绝对角（没接陀螺仪显示 `NO GYRO`） |
| 3 | `MEA +089.63`：当前绝对角（带两位小数） |
| 4 | `ERR +000.37 OK` / `ERR -002.10 FAIL` |

闭环实现（`gyro_turn_to_abs`）：

1. 每次都是"转到某个**绝对角度**"，不是相对转多少度 → 多段路线之间不累积偏差；
2. **按误差直接算脉冲**：`脉冲 = |误差| / 36000 × MOTOR_PULSE_PER_360DEG`，误差 10° 就发 478 脉冲，
   误差 36° 就发 1720 脉冲，一步到位；
3. **等车体停稳再测**（100 ms 间隔两次角度差 < 0.5°），再读全局角重算误差，最多补 15 次；
4. 误差 ≤ 0.1° 算到位，补差用尽后残留 ≤1° 也接受。

### 7.3 其它调试模式（改 `main.c` 顶部的 `DEBUG_MODE` 切换）

| 宏 | 模式 | 用途 |
|---|---|---|
| `DEBUG_MODE_ROUTE`（3，**当前默认**） | 全图路线 | 见 7.1，转向走 7.2 的同一个闭环实现 |
| `DEBUG_MODE_TURN`（4） | 闭环旋转测试 | 见 7.2 |
| `DEBUG_MODE_MOTOR`（2） | 电机方向 / 地址自检 | 换电机后核对"地址 ↔ 轮子"和转向 |
| `DEBUG_MODE_CIRCLE`（1） | K230 圆心跟踪 | USART2 收 `x,y\r\n`，让圆心停在 (320,240) |
| `DEBUG_MODE_SERVO`（0） | 舵机角度按键标定 | PA12 +1°、PA11 −1° |
| `DEBUG_MODE_CHASSIS`（5） | **速度模式底盘自检（新增）** | 测试 `chassis.c`：前进/平移/旋转/1000 mm 标定 |
| `DEBUG_MODE_WIRELESS`（6） | **无线串口底盘测试（新增）** | USART3 + 上位机 `tools/chassis_host.py` 遥控/看角度 |

> 调参数只改一处。路线跑完的 `PATH DONE` 画面第 3 行会显示最后一次转向的补差次数 `C` 和残留误差 `E`。

**电机自检模式**：这块板子只有 3 个键可用——**PA8 翻页、PA12 本页第 1 个动作、PA11 本页第 2 个动作**。
每个动作发完都用 `judge_wait(40)` 等四轮到位（约 9 s 超时显示 `NO ANSWER`，不会再像以前那样卡住）。

| 页 | PA12 | PA11 |
|---|---|---|
| P1 | 前进 40 mm | 后退 40 mm |
| P2 | 左平移 40 mm | 右平移 40 mm |
| P3 | 逆时针 15° | 顺时针 15° |
| P4 | 逆时针 90° | 顺时针 90° |
| P5 | 地址 1 正转点动 | 地址 1 反转点动 |
| P6 | 地址 2 正转点动 | 地址 2 反转点动 |
| P7 | 地址 3 正转点动 | 地址 3 反转点动 |
| P8 | 地址 4 正转点动 | 地址 4 反转点动 |

P5~P8 一次只有一个轮子动（约 30 mm，30 rpm），动的是哪个轮子，那个地址就是它；
正/反各点一次还能顺带看出该轮的转向极性。
确认后改 [motor.h](app/motor.h) 里的 `MOTOR_ADDR_FL/FR/RL/RR` 四个宏即可，运动函数体里不再写死 1/2/3/4。

**速度模式底盘自检（`DEBUG_MODE_CHASSIS`）**：同样 **PA8 翻页、PA12 第 1 个动作、PA11 第 2 个动作**，
5 页：

| 页 | PA12 | PA11 |
|---|---|---|
| P1 | 前进 100 mm | 后退 100 mm |
| P2 | 左平移 100 mm | 右平移 100 mm |
| P3 | 逆时针 90° | 顺时针 90° |
| P4 | 前进 1000 mm | 后退 1000 mm（量实际距离，调 `CHASSIS_TIME_GAIN_PCT`） |
| P5 | 前进 500 mm @15 RPM | 前进 500 mm @70 RPM |

每页动作完显示 `OK` / `ABORT`；**运动中按 PA8 立即停车**。
改完 chassis 参数可以在电脑上先跑 `tmp_chassis_test` 里的回归测试（见该目录说明，不需要硬件）。

**无线串口底盘测试（`DEBUG_MODE_WIRELESS`）**：USART3 接无线串口模块（115200、8N1），
上电显示 `WIRELESS / WAIT CMD`，电脑端运行：

```powershell
pip install -r tools/requirements.txt     # 只需一次
python tools/chassis_host.py
```

| 发送 | 作用 |
|---|---|
| `F 1000` `B 1000` | 前进 / 后退 1000 ms |
| `L 1000` `R 1000` | 左平移 / 右平移 1000 ms |
| `Q 1000` `E 1000` | 逆时针 / 顺时针 1000 ms |
| `S` | 立即停车 |
| `D` | 内置测试：前进 1s → 逆时针 1s → 后退 1s → 顺时针 1s |
| `?` / `P` / `V 300` | 查角度 / ping / 设默认速度 0.1RPM |

- 数字可省略（默认 1000 ms），`F1000` 和 `F 1000` 都行；回包 `ACK/DONE/ABORT/YAW`；
- 空闲时按 **PA8** 也能跑一次内置测试，运动中按 PA8 立即停车；
- 想上电自动跑一次，把 `main.c` 里 `WIRELESS_AUTO_DEMO` 改成 `1`；
- 详细接线、界面和协议见 [tools/README.md](tools/README.md)。

**K230 跟踪模式**的映射与参数（改相机朝向时只需改这几处）：

- `y > 240` → 向右平移 `you_()`，`y < 240` → 向左平移 `zuo_()`；
- `x > 320` → 后退 `houtui_()`，`x < 320` → 前进 `qianjin_()`；
- 比例 **60 px ≈ 35 mm**，单步限幅 40 mm，死区 ±8 px（约 5 mm）；
- 每发一步都 `judge()` 等四个电机回 0x03 之后才取下一帧；没有新帧时不下发任何指令；
- OLED：1 行 `K230 TRACK`、2 行右侧 `JCNT` + `judge` 计数、3 行 `X=xxx Y=xxx`、4 行方向与步长。

> 每个模式函数内部都是死循环（不会返回），所以同一时间只有 `DEBUG_MODE` 选中的那一套在跑。

## 8. 已知问题 / 坑（以后回来先看这里）

1. **引脚冲突**：PA2 = USART2_TX 和 LED2。
   初始化顺序上 USART2 覆盖 LED2，所以当前固件里 **LED2 实际不可用**；OLED 现已改为硬件 I2C1（PB6=SCL、PB7=SDA，400 kHz）。
2. **方向表是实测出来的，别照教科书改**：换电机后实测发现滚子朝向是"同手"的，
   `qianjin_/houtui_/zuo_/you_` 里的方向位已是现场逐项试出的表（见 4.5）。
   地址用 `MOTOR_ADDR_*` 配、单轮极性用 `MOTOR_DIR_INV_*` 配、旋转整体方向用 `MOTOR_YAW_SWAP`（都在 `app/motor.h`）。
3. **旋转标定未完成**：`MOTOR_PULSE_PER_360DEG` 是占位值。
4. **F6 帧格式有两种说法**：字段说明写「加速度 0~65535、速度 0~7E30」（9 字节），
   但示例帧 `01 F6 00 00 32 32 01 6B` 是 8 字节。`chassis_config.h` 两种都实现了，
   默认 8 字节（和示例帧逐字节一致）；如果驱动器没反应，先对照手册确认是不是要改成
   `CHASSIS_FRAME_LAYOUT_9B`。
5. **网格 y 轴间距不均匀**：`2250→1725→1200` 是 Δ525，`1200→625` 是 Δ575、`625→150` 是 Δ475，
   疑似 `625` 应为 `675`。
6. `mingling/` 目录已废弃（12 字节缺 0xFD 的旧指令），被 `motor.c` 动态组帧取代。
7. `User/stm32f10x_it.c` 的中断函数都是空壳，真正的 USART1/USART2/USART3 中断在 `Serial.c` 里实现；USART3 接收按行解析，给无线串口用。

## 9. 快速上手

1. Keil 打开 `Project.uvprojx`，编译（默认已配好 72MHz + 标准库）。
2. FlyMcu 通过串口（BOOT0=1）烧录。
3. 接线：电机 → USART1(PA9/PA10)。
4. 把小车放在 `(2250,2250)`（A=起点1，右上角），按上面 7.1 选好车头朝向与 `PATH_INITIAL_DIR`；
   上电后有 3 s 倒计时，然后自动跑完 8 段；OLED 显示 `PATH DONE` 表示完成，
   `PATH ERROR` 表示规划失败或等电机超时，跑飞时按 **PA8** 中止（段与段之间生效）。
