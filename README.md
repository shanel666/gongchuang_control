# 四麦轮小车（工程创新比赛）— STM32F103C8T6

> 本工程：基于 STM32F103C8T6 的四轮麦克纳姆轮小车，4 个「张大头」闭环步进电机驱动，
> 在 2.25 m × 2.25 m 网格场地上自动规划路径、避开障碍物，从起点走到终点。
> 当前主程序上电后自动依次经过指定坐标，完成路线后停机显示状态。

## 3. 两个串口的分工（重要！）

工程里有两个串口，**用途完全不同，接错线就“没反应”**：

| 串口 | 引脚 | 接什么 | 用途 |
|---|---|---|---|
| **USART1** | PA9(TX) / PA10(RX) | 电机总线 | 发运动指令、读位置 |
| **USART2** | PA2(TX) / PA3(RX) | JY901 兼容陀螺仪（可选 USB-TTL 调试） | 115200、8N1；接收并校验 0x55 0x53 角度帧，同时保留 `k:数字` 调试命令 |
| **USART3** | **PB10(TX)** / PB11(RX)（默认映射） | 上位机 USB-TTL | 115200、8N1；输出可直接阅读的角度文本 |

- 陀螺仪 TX 接 **PA3（USART2_RX）**，陀螺仪 RX 可接 **PA2（USART2_TX）**，并与单片机共地，波特率 **115200**、8N1。
- 上位机 USB-TTL 的 RX 接 **PB10（USART3_TX）**，GND 共地；打开串口工具选择这个 USB-TTL 对应的 COM 口。
- USART2 的电脑串口助手仍可接 PA2/PA3 做 `k:数字` 调试；USART3 只输出角度文本。
- USART3 使用 PB10/PB11 后，PB10 对应的第 3 个按键不可再使用。
- 电机的 4 个从机都挂在 **USART1** 一条总线上，地址 1~4。

### 3.1 陀螺仪角度读取

`Hardware/Gyro.c` 在 USART2 接收中断中逐字节解析 JY901/WitMotion 兼容协议。只有帧头为 `55 53` 且第 11 字节校验和正确时，才更新 Z 轴（Yaw）数据。当前 `main` 中的临时测试循环每 200 ms 通过 USART3 输出一次最新角度，例如 `-12.34`：

- `Gyro_GetYawRaw()`：返回有符号 16 位原始值；
- `Gyro_GetYawCentiDegrees()`：返回百分之一度，换算关系为 `raw × 18000 / 32768`；
- USART3 输出格式为 `正负号/整数部分.两位小数\r\n`，单位为度，输出频率 5 Hz；
- 主程序把最近一次有效角度显示在 OLED 第 4 行，未收到有效帧时不会误报数据。

## 4. 电机通信协议

### 4.1 运动帧（13 字节）

```
[地址][0xFD][方向][速度H][速度L][加速度][脉冲B3][脉冲B2][脉冲B1][脉冲B0][模式][同步][0x6B]
```

| 偏移 | 含义 | 说明 |
|---|---|---|
| [0] | 地址 | FL=0x01, FR=0x02, RL=0x03, RR=0x04 |
| [1] | 命令 | 0xFD |
| [2] | 方向 | 0x00 正转 / 0x01 反转 |
| [3..4] | 速度 | 大端 2 字节 |
| [5] | 加速度 | 1 字节 |
| [6..9] | 脉冲数 | 大端 4 字节 |
| [10] | 模式 | 0x00 相对 / 0x01 绝对位置 |
| [11] | 同步 | 0x00 立即执行 / 0x01 等同步帧 |
| [12] | 校验 | 固定 0x6B |

### 4.2 旋转速度模式（8 字节）

陀螺仪 PD 转弯测试使用电机的 F6 速度模式：

```
[地址][0xF6][方向][速度H][速度L][加速度][同步][0x6B]
```

方向 `0x00=CW`、`0x01=CCW`；速度为 0~3000 RPM 的大端值；加速度为 0~255 档；同步标志为 `0x00` 时立即执行。当前测试使用加速度 10 档、最高 1500 RPM，发送速度 0 停止电机。有效应答格式为 `[地址][0xF6][0x02][0x6B]`。

### 4.3 其它帧

- **同步释放帧** `00 FF 66 6B`：直行时 4 电机都设 sync=0x01，最后发这帧让它们**同时起步**。
- **使能帧** `[addr] F3 AB 01 00 6B`：上电默认失能，运动前 `motor_enable_all()` 依次使能。
- **读位置** `[addr] 36 6B` → 回 8 字节 `[addr] 36 [dir] [pos×4] 6B`。

### 4.4 麦轮方向表（2026-10-23 换电机后实测标定）

这四个轮子的滚子朝向是"同手"的（不是常规左右镜像），所以映射和教科书不同：
**前进是"对角轮一组"，平移是"前后一组"，四个轮子同向才是旋转**。
下表是实际发出去的方向位（0x00 / 0x01），`MOTOR_DIR_INV_*` 目前全 0：

| 动作 | FL(1) | FR(2) | RL(3) | RR(4) |
|---|---|---|---|---|
| 前进 `qianjin_` | 1 | 0 | 0 | 1 |
| 后退 `houtui_` | 0 | 1 | 1 | 0 |
| 左平移 `zuo_` | 1 | 1 | 0 | 0 |
| 右平移 `you_` | 0 | 0 | 1 | 1 |
| 左旋 `ni_yaw_` | 1 | 1 | 1 | 1 |
| 右旋 `shun_yaw_` | 0 | 0 | 0 | 0 |

> 现场微调三个开关（都在 `app/motor.h`，改一个数、重编译即可，不用动上面的表）：
> `MOTOR_FLIP_FWD=1u`（前后轴整体反了）、`MOTOR_FLIP_LAT=1u`（左右轴整体反了）、
> `MOTOR_YAW_SWAP=1u`（旋转整体反了）。

> - 旧版"平移 = 四轮同向"其实是转圈，已按实测改掉；
> - "左右一组"（FL 1 / FR 0 / RL 1 / RR 0）会让四个轮子互相抵消，车原地不动，别用；
> - 旋转顺时针/逆时针哪个是哪个、以及左平移/右平移是否互换，用 P2/P3 现场确认，
>   反了只需改 `MOTOR_YAW_SWAP` 或把 `zuo_()/you_()` 两张表对调。

## 6. 路径规划

- **5×5 网格**，25 个交点，坐标单位 mm：

| | col0 | col1 | col2 | col3 | col4 |
|---|---|---|---|---|---|
| **x** | 150 | 675 | 1200 | 1725 | 2250 |
| **y** | 2250 | 1725 | 1200 | 625 | 150 |

- 障碍在 `app/path_config.h` 配置，`PATH_OBSTACLE_0..3` 默认是 4 个交叉口：
  `(675,1725)(1725,1725)(675,625)(1725,625)`。
- `path_plan(起点, 终点, ...)` 用 **Dijkstra** 算最短路，再提取「起点 + 拐弯点 + 终点」作为关键点，
  结果存 `xpath[]/ypath[]`，个数在全局 `key_point_num`。
- 附 `PATH_PLANNER_DEMO` 宏，可在 PC 上 `gcc -DPATH_PLANNER_DEMO path_planner.c` 单独验证算法。

## 7. 主程序流程

### 7.1 当前默认：全图路线状态机（`DEBUG_MODE_ROUTE`）

上电 → 初始化（LED/舵机/OLED/按键/USART1-3/陀螺仪）→ `motor_enable_all()` →
OLED 显示起点 → **3 秒倒计时**（此时摆车）→ 进入 `route_run()` 的 `while(1)`。

**状态就是"第几段"**：`step = 1..8`，OLED 第 1 行显示 `CASE n/8`。每跑完一段 `step++`，
最后 `step = 99`（`PATH DONE`）；失败 `98`（`PATH ERROR`），按 PA8 中止 `97`（`ABORT BY PA8`）。

```c
while(1){
    /* 顶栏显示 CASE n/8，4 行 AT 当前坐标；TO 由 leg_goto() 进来时画 */
    switch(step){
        case 1: step = leg_goto(2250u, 1200u) ? 2u : (abort_flag ? 97u : 98u); break;  /* → E 堆码 */
        case 2: step = leg_goto(1200u, 2250u) ? 3u : (abort_flag ? 97u : 98u); break;  /* → B 原料 */
        ...
        case 8: step = leg_goto(2250u, 2250u) ? 99u : (abort_flag ? 97u : 98u); break; /* → 回到起点 */
        case 99: /* PATH DONE */   case 98: /* PATH ERROR */   case 97: /* ABORT */
    }
}
```

**每个 case 就是"去哪个点"**，目标坐标直接写在 case 里；到了就把 `step` 换成下一个。
`leg_goto(tx, ty)` 内部：`path_plan()` 拆成直角小段 → 每小段先 `leg_face()` 对准朝向
→ `qianjin_/houtui_` 走完 → `wait_motors()`（有界等待，驱动器掉线不会卡死）。
它一进来就把 `TO x,y` 画到第 3 行；走完更新 `fsm_x/fsm_y`，第 4 行 `AT` 跟着变。

**陀螺仪闭环转向**（`gyro_turn_by`，骨架沿用旧版 `gyro_turn_pos_test`）：

1. 按标定值把 ±90° **整个走完**（不拆成小步）；
2. 第一次实测后估一次"指令角度→实际转角"的增益（0.5~2.0 倍），之后补差按 **误差/增益** 计算，
   标定不准也能 1~2 次收敛；估不出增益时退回旧版 `Kp=0.5`；
3. **补差量必须换算成"度"再发给电机**（`err` 是 0.01°，直接发会每次被限幅成 30° → 这就是之前超调的原因）；
4. 误差 ≤ 0.1° 且**连续 3 帧**稳定才算到位，最多补 5 次；用尽后残留 ≤1° 也算到位。

其它：任何阶段按 **PA8** 中止；陀螺仪没数据时转向退化为开环 90°（第 2 行显示 `NO GYRO`）；
转到一半角度流断掉则 `PATH ERROR` 停车，不会带着错误朝向继续跑。

路线（起点 `PATH_START_X/Y = (2250,2250)`，即场地图的 A=起点1）：

| 段 | 目标 | 场地点 |
|---|---|---|
| 1 | (2250,1200) | E 堆码 |
| 2 | (1200,2250) | B 原料 |
| 3 | (1200,150)  | C 粗加工 |
| 4 | (150,1200)  | D 暂存 |
| 5 | (1200,2250) | B |
| 6 | (1200,150)  | C |
| 7 | (150,1200)  | D |
| 8 | (2250,2250) | A 终点（回到起点） |

> - 每个 case 就是一次 `leg_goto(x, y)`，增删站点直接改 `main.c` 里那一行；
> - 起点坐标和初始朝向在 `app/path_config.h`（`PATH_START_*`、`PATH_INITIAL_DIR`）；
> - `PATH_INITIAL_DIR=1`（朝北）时第一段会**倒车** 1050 mm；若上电时把车头朝**南**摆，
>   把 `PATH_INITIAL_DIR` 改成 `3`，第一段就是正着前进；
> - 用"完美闭环"离线推演过整条路线：8 段 13 个动作，最终精确回到 `(2250,2250)`。

### 7.2 闭环旋转单独测试（`DEBUG_MODE_TURN`）

不跑路线，只测 `gyro_turn_by()` 这一个函数——它就是路线里用的同一份闭环转向实现。

| 按键 | 动作 |
|---|---|
| **PA12** | 逆时针（左转）转当前档位角度 |
| **PA11** | 顺时针（右转）转当前档位角度 |
| **PA8** | 切换档位 15° → 45° → 90° → 15° … |

每次转完把过程量留在屏幕上，便于定位问题：

| 行 | 内容 |
|---|---|
| 1 | `TGT+090 C3 G102`：目标角度、补差次数、估计增益×100（`G0` = 没估出来，退回了 Kp=0.5） |
| 2 | 左半是 `judge` 查询计数，右侧 `Y±ddd` 是陀螺仪实时角度（没接陀螺仪显示 `NO GYRO`） |
| 3 | `MEA +089.63`：实测相对转角 |
| 4 | `ERR +000.37 OK` / `ERR -002.10 FAIL` |

闭环实现（`gyro_turn_by`）的四个要点：

1. 先按标定值把 ±90° **整个走完**，不拆小步；
2. **等车体停稳再测**（间隔 100 ms 两次角度差 < 0.5° 才算停稳，最多等 0.5 s）——
   电机报"到位"只代表脉冲发完，车体还会晃，不等稳就测会反复过冲；
3. 用第一次实测估值增益（0.5~2.0 倍），之后补差 = 误差/增益，**换算成"度"再发**；
4. 误差 ≤ 0.1° 且连续 3 帧稳定算到位，最多补 5 次，用尽后残留 ≤1° 也接受。

### 7.3 其它调试模式（改 `main.c` 顶部的 `DEBUG_MODE` 切换）

| 宏 | 模式 | 用途 |
|---|---|---|
| `DEBUG_MODE_ROUTE`（3，**当前默认**） | 全图路线 | 见 7.1，转向走 7.2 的同一个闭环实现 |
| `DEBUG_MODE_TURN`（4） | 闭环旋转测试 | 见 7.2 |
| `DEBUG_MODE_MOTOR`（2） | 电机方向 / 地址自检 | 换电机后核对"地址 ↔ 轮子"和转向 |
| `DEBUG_MODE_CIRCLE`（1） | K230 圆心跟踪 | USART2 收 `x,y\r\n`，让圆心停在 (320,240) |
| `DEBUG_MODE_SERVO`（0） | 舵机角度按键标定 | PA12 +1°、PA11 −1° |

> 闭环转向只有一份实现（`gyro_turn_by` / `gyro_turn_settle`），路线和测试模式共用；
> 调参数只改一处。路线跑完的 `PATH DONE` 画面第 3 行会显示最后一次转向的增益 `G` 和补差次数 `C`。

**电机自检模式**：这块板子只有 3 个键可用——**PA8 翻页、PA12 本页第 1 个动作、PA11 本页第 2 个动作**。
每个动作发完都用 `judge_wait(40)` 等四轮到位（约 9 s 超时显示 `NO ANSWER`，不会再像以前那样卡住）。

| 页 | PA12 | PA11 |
|---|---|---|
| P1 | 前进 40 mm | 后退 40 mm |
| P2 | 左平移 40 mm | 右平移 40 mm |
| P3 | 逆时针 15° | 顺时针 15° |
| P4 | 逆时针 90° | 顺时针 90° |
| P5 | 地址 1 正转点动 | 地址 1 反转点动 |
| P6 | 地址 2 正转点动 | 地址 2 反转点动 |
| P7 | 地址 3 正转点动 | 地址 3 反转点动 |
| P8 | 地址 4 正转点动 | 地址 4 反转点动 |

P5~P8 一次只有一个轮子动（约 30 mm，30 rpm），动的是哪个轮子，那个地址就是它；
正/反各点一次还能顺带看出该轮的转向极性。
确认后改 [motor.h](app/motor.h) 里的 `MOTOR_ADDR_FL/FR/RL/RR` 四个宏即可，运动函数体里不再写死 1/2/3/4。

**K230 跟踪模式**的映射与参数（改相机朝向时只需改这几处）：

- `y > 240` → 向右平移 `you_()`，`y < 240` → 向左平移 `zuo_()`；
- `x > 320` → 后退 `houtui_()`，`x < 320` → 前进 `qianjin_()`；
- 比例 **60 px ≈ 35 mm**，单步限幅 40 mm，死区 ±8 px（约 5 mm）；
- 每发一步都 `judge()` 等四个电机回 0x03 之后才取下一帧；没有新帧时不下发任何指令；
- OLED：1 行 `K230 TRACK`、2 行右侧 `JCNT` + `judge` 计数、3 行 `X=xxx Y=xxx`、4 行方向与步长。

> 每个模式函数内部都是死循环（不会返回），所以同一时间只有 `DEBUG_MODE` 选中的那一套在跑。

## 8. 已知问题 / 坑（以后回来先看这里）

1. **引脚冲突**：PA2 = USART2_TX 和 LED2。
   初始化顺序上 USART2 覆盖 LED2，所以当前固件里 **LED2 实际不可用**；OLED 现已改为硬件 I2C1（PB6=SCL、PB7=SDA，400 kHz）。
2. **方向表是实测出来的，别照教科书改**：换电机后实测发现滚子朝向是"同手"的，
   `qianjin_/houtui_/zuo_/you_` 里的方向位已是现场逐项试出的表（见 4.4）。
   地址用 `MOTOR_ADDR_*` 配、单轮极性用 `MOTOR_DIR_INV_*` 配、旋转整体方向用 `MOTOR_YAW_SWAP`（都在 `app/motor.h`）。
3. **旋转标定未完成**：`PULSE_PER_360DEG` 是占位值。
4. **网格 y 轴间距不均匀**：`2250→1725→1200` 是 Δ525，`1200→625` 是 Δ575、`625→150` 是 Δ475，
   疑似 `625` 应为 `675`。
5. `mingling/` 目录已废弃（12 字节缺 0xFD 的旧指令），被 `motor.c` 动态组帧取代。
6. `User/stm32f10x_it.c` 的中断函数都是空壳，真正的 USART1/USART2 中断在 `Serial.c` 里实现；USART3 仅发送，不使用接收中断。

## 9. 快速上手

1. Keil 打开 `Project.uvprojx`，编译（默认已配好 72MHz + 标准库）。
2. FlyMcu 通过串口（BOOT0=1）烧录。
3. 接线：电机 → USART1(PA9/PA10)。
