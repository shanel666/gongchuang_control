# 智能小车 —— 视觉追圆心（STM32F103C8T6 + 勘智 K230）

> **一句话**：F103 当主控，通过 USART2 让 K230 算"圆心坐标 / 三条线的斜率与偏航"，
> 主控把像素偏差换成毫米，用**很慢的位置模式**一小步一小步把圆心拉到"夹爪正下方"。
> 抓取动作（舵机 + 升降 + 物料分度）已经写好并能手动跑通，但**"识别颜色 → 自动去抓"这条链子还没连起来**。

## 1. 硬件

### 1.1 板子换了：RCT6 → C8T6（烧毁换板，迁移已完成）

| | 旧：STM32F103**RCT6** | 新：STM32F103**C8T6** | 影响 |
|---|---|---|---|
| 封装 | LQFP64 | LQFP48 | 引脚少了 16 个 |
| Flash / RAM | 256 KB / 48 KB | **64 KB / 20 KB** | 实测只用了 23 KB / 1.5 KB，**不缺** |
| 可用 IO | PA/PB/PC 全 + PD0/PD1 | PA0-15、PB0-15、**只有 PC13/14/15** | ★ **PC0~PC12 全没了** |

**由此产生、已经改好的两处硬件变化：**

1. **舵机换脚**：旧设计三路舵机在 PC7/PC8/PC9（C8T6 上没有），现在改成
   **PA0 = 夹爪、PA1 = 旋转**（TIM2_CH1 / TIM2_CH2）；原来的"升降舵机"改成了**步进电机（地址 6）**。
2. **PA2 弃用**：实测 PA2（TIM2_CH3）输出异常 —— 舵机信号线挪到 PA1 才动，疑似该脚损坏。
   所以 PA2 现在只当 **USART2_TX**（给 K230 发命令）。

> 代码里已经没有 PC0~PC12 的引用（我核对过），C8T6 引脚够用。

### 1.2 引脚分配表（接线就看这张）

| 功能 | 引脚 | 外设 | 备注 |
|---|---|---|---|
| **步进总线** | **PA9**(TX) / **PA10**(RX) | USART1 | 四轮(1~4) + 物料(5) + 升降(6) 全挂这条线；**也是烧写口** |
| **K230** | **PA2**(TX) / **PA3**(RX) | USART2 | 115200 8N1。K230 的 GH1.25「串口2」丝印顺序 **V-R-T-G**：T→PA3、R←PA2、G→GND，**V(5V) 不接** |
| **调试** | **PB10**(TX) / **PB11**(RX) | USART3 | 115200，`printf` 都走这里（OLED 之外唯一观测口） |
| OLED | **PB6**(SCL) / **PB7**(SDA) | I2C1 硬件 | 从机地址 0x78，100 kHz |
| 夹爪舵机 | **PA0** | TIM2_CH1 | 0~270°，初始 85° |
| 旋转舵机 | **PA1** | TIM2_CH2 | 0~270°，初始 30°；放料位 115° |
| ~~PA2~~ | — | TIM2_CH3 | **该脚异常，弃用** |
| 按键 **PB1** | PB1 | GPIO 下拉 | 按下为**高**。视觉模式：切模式 / 夹取单步 |
| 按键 **PA7** | PA7 | GPIO 下拉 | 按下为**高**。视觉模式：点动自检 / 夹取连跑 |
| 按键 **PA5** | PA5 | GPIO 下拉 | 按下为**高**。视觉模式：急停 / 夹取中止 |
| 按键 PA8 | PA8 | GPIO **上拉** | 按下为**低**。跑图/转向/电机自检模式用它（视觉模式不用） |
| LED | **PC13** | GPIO | **低电平点亮** |
| PC14/PC15 | PC14/PC15 | GPIO | 只有 PC 按键自检模式用，平时输出高 |

### 1.3 三个串口，别接错

| 串口 | 波特率 | 接什么 | 用途 |
|---|---|---|---|
| USART1 | 115200 | 6 个张大头驱动器 | **二进制**命令帧（ASCII 会当垃圾丢掉） |
| USART2 | 115200 | K230 或 陀螺仪（**二选一**） | 收 ASCII 坐标帧 / 收 0x55 0x53 角度帧 |
| USART3 | 115200 | USB-TTL / 无线模块 | 调试打印，`DEBUG_MODE_WIRELESS` 时也收上位机命令 |

### 1.4 供电（最容易翻车的地方）

**症状**：电机一动，K230 就重启掉线。这是**电源被拉塌**，不是程序问题。

| 优先级 | 措施 |
|---|---|
| 1 | **K230 用独立供电**（自己的充电宝/适配器），**不要**和驱动器共用一个 5V |
| 2 | K230 的 5V 就近并 **470 µF 电解 + 0.1 µF 瓷片** |
| 3 | **GND 加粗、缩短** —— 地弹是"随机重启"的头号原因 |
| 4 | 驱动器 24V 端子并 **470~1000 µF** |
| 5 | 电机线（PA9/PA10）和 K230 的信号线/USB 线**分开走** |

程序这边已经做了能做的：速度 8 RPM、加速度档 8、单步 ≤6 mm、每步后停 150 ms、
举高从 60 RPM 降到 40 RPM、**K230 掉线会自动重发模式命令**（§3.3）。

## 3. 软件架构

### 3.1 分层

```
        ┌─────────────────────────────────────────────┐
  业务层 │ vision.c  motion.c  material_motor.c  lift_motor.c │
        │ (追圆心)   (走一段/到某点)  (物料分度)      (升降)   │
        ├─────────────────────────────────────────────┤
  动作层 │ motor.c（位置模式 FD，梯形加减速）          │
        │ chassis.c（速度模式 F6，定时运动）           │
        ├─────────────────────────────────────────────┤
  驱动层 │ Serial.c  OLED.c  Gyro.c  Key.c  Servo.c  LED.c │
        ├─────────────────────────────────────────────┤
  硬件层 │ USART1/2/3  I2C1  TIM2  GPIO                  │
        └─────────────────────────────────────────────┘
```

**一条规矩**：上层只调下层；驱动层不认识业务。所以 `OLED.c` 里只有"写字/清行/格式化"，
"该显示什么"永远在业务层。

### 3.2 一帧 K230 数据的生命周期

```
K230 每 ~300 ms 发一行 "C541,159,70\r\n"
        ↓ USART2 接收中断（Serial.c）
逐字节丢进环形缓冲，白名单过滤（只收 0-9 A-Z a-z , + - 空格）
        ↓
遇到 '\n' 调用 K230_ParseLine()（★ 纯函数，可在 PC 上单测）
        ↓
写入全局：K230_Cx/Cy/R、K230_CircleSeq++       ← 序号是关键
        ↓
主循环发现 K230_CircleSeq 变了 → 说明有新数据
        ↓
vision_circle_issue() 算一步 → vision_move_fwd/lat() 发一帧给驱动器
        ↓
vision_step_ms() 估算"这一步要多久" → v_wait 倒计时（不阻塞！）
```

**为什么用序号而不是标志位**：序号能保证"同一帧只执行一次"，而且主循环忙的时候
中间来的帧会被自然跳过、永远只用最新那帧。

### 3.3 闭环时序（一次纠正）

```
t=0     新帧到达（seq+1）
t=0     算 dX = 541-541 = 0、dY = 159-159 = 0 → 死区内，不动
t=300   新帧 C571,189 → dX=+30 dY=+30 → 先修大的轴（都是 30，先 x）
        → "BACK 6mm"（dx>0→前进？见 §6.2，当前配置是前进）
        → 估算 need≈363ms → v_wait = 91 圈
t=0~363 等 91 圈：主循环照常收帧、刷屏、响应按键（★ 不卡）
t=363   允许下一步 → 用**最新**那一帧重新算
```

## 4. 协议

### 4.1 F103 ↔ K230（ASCII，115200 8N1）

**下行（F103 → K230）**，每行以 `\r\n` 结尾：

| 命令 | 含义 | K230 行为 |
|---|---|---|
| `circle` | 找圆 | 只找圆，回 `C` 帧 |
| `linear` | 看三环 | 找圆 + 拟合三条线，回 `L` 帧 |
| `stop` | 停 | 回 IDLE，不再回数据 |

**上行（K230 → F103）**：

| 帧 | 例子 | 字段含义 |
|---|---|---|
| `C<x>,<y>,<r>` | `C541,159,70` | 圆心像素坐标、半径 |
| `L<k>,<psi>` | `L4,192` | `k` = 斜率×100；`psi` = 偏航角×100（0.01°，**正 = 顺时针**） |
| `NG` | `NG` | 没找到目标（只记数，**绝不动作**） |

规则：单帧最长 **16 字符**，超长整帧丢弃直到换行；只接受 `0-9 A-Z a-z , + - 空格`。
`k=4` 表示 0.04；`psi=192` 表示 1.92°。

### 4.2 F103 ↔ 步进驱动器（二进制，13 字节）

```
[地址][0xFD][方向][速度H][速度L][加速度][脉冲B3][B2][B1][B0][模式][同步][0x6B]
```

| 偏移 | 含义 |
|---|---|
| 0 | 地址：轮 1~4、物料 5、升降 6 |
| 1 | `0xFD` = 位置模式 |
| 2 | 方向 `0x00` / `0x01` |
| 3..4 | 速度 RPM（大端） |
| 5 | **加速度档 0~255，越小斜坡越缓** |
| 6..9 | 脉冲数（大端，13 脉冲/mm） |
| 10 | `0x00` 相对 / `0x01` 绝对 |
| 11 | `0x00` 立即 / `0x01` 等同步帧 |
| 12 | 固定 `0x6B` |

其它帧：**急停** `[addr] FE 98 00 6B`、**使能** `[addr] F3 AB 01 00 6B`、
**查到位** `[addr] 3A 6B` → 回 `[addr] 3A 03 6B`（状态 `0x03` = 到位）。

### 4.3 麦轮方向表（实测，**别照教科书改**）

滚子是"同手"的，所以前进是**对角轮一组**，平移是**前后一组**：

| 动作 | FL(1) | FR(2) | RL(3) | RR(4) |
|---|---|---|---|---|
| 前进 | 1 | 0 | 0 | 1 |
| 后退 | 0 | 1 | 1 | 0 |
| 左移 | 1 | 1 | 0 | 0 |
| 右移 | 0 | 0 | 1 | 1 |
| 逆时针 | 1 | 1 | 1 | 1 |
| 顺时针 | 0 | 0 | 0 | 0 |

整轴反了改 [motor.h](app/motor.h) 的 `MOTOR_FLIP_FWD/LAT/YAW_SWAP`；
单轮反了改 `MOTOR_DIR_INV_1..4`。**视觉方向反了不要动这张表**，改 §6.2 的宏。

### 4.4 K230 端要点

```python
BAUD = 115200     # 和 F103 一致
UART_ID = 2       # K230 的 UART2 = GPIO11(TX) / GPIO12(RX)
IMG_W, IMG_H = 800, 450      # ★ 像素级 16:9（1920x1080 × 0.4167），不裁不拉
USE_DISPLAY = True           # 没接屏也能跑，看 IDE 帧缓冲
USE_DISPLAY_LCD = True       # 接着 3.1 寸屏就 True（面板+IDE 都有图）；没接改 False
STRIDE = 1        # 改成 2 可让找圆快约 1.6 倍（坐标不变）
```

**★ 为什么是 800x450，而显示却要"合成画布"**

实测（[vision/LCD自检.py](vision/LCD自检.py) 的矩阵）出两个结论：

1. `image.Image` 造的 **800×450 @(0,15) 能上屏**；但把 `sensor.snapshot()` 的**相机帧**
   直接 `show_image` 就报 `set vo layer attr failed 1`，屏整块不刷 —— 这就是之前那次"黑屏"。
2. 所以每帧先 `draw_image` 到一张 800×480 的画布上，再整张送屏（多一次 ~720 KB blit，
   K230 上 1~3 ms）。`show()` 里三种方式（direct / composite / copy）启动时自动试，
   哪个能用就固定用哪个，并打印出来。

| 候选 | 结果 |
|---|---|
| 640×480（老配置） | 4:3，横向裁掉 25% → "拍不全" |
| **800×450（现在）** | **像素级 16:9，全视野不裁不拉**；靠合成画布上屏，屏上上下各 15 px 黑边 |
| 800×480（备选） | 图像==画布、最省事，但相对 16:9 差 6.7%（拉伸或裁掉约 6% 宽） |

**★ 坐标只有一套**：图像像素坐标。串口发的、`draw_xxx` 画的、算 dx/dy 用的都是它。
显示层的 (x,y)（800×450 贴 y=15）只决定"贴在屏上哪儿"，**不参与任何坐标计算**。

**★ 一次运行只有一种 VO 输出**：走 `Display.VIRT` 就只有 IDE 有画面、**面板全黑**；
走 `Display.ST7701` 才面板+IDE 都有。所以"LCD 黑屏但 IDE 有图"就是模式选错了，
不是屏坏了 —— 改 `USE_DISPLAY_LCD`。

**没接屏是正常的** —— 主板上没有屏，3.1 寸屏是扩展板。初始化失败也不影响串口（有 try/except 兜底）。

**怀疑屏/显示有问题**：单独跑 [vision/LCD自检.py](vision/LCD自检.py)（完全不碰相机），
它会：① 红/绿/蓝/白格子确认屏和显示通路；② 打印一组 (w,h,x,y) 组合哪些能被 VO 接受；
③ 测"合成画布"能不能做像素级 16:9。

### 6.2 方向标定（★ 再也不靠猜）

**按 PA7** 会依次点动 前进/后退/左移/右移/顺转/逆转，并量出"这一下让圆心坐标变了多少"：

```
JOG AHEAD            ← 程序发了什么
dx+18 dy-3           ← 坐标变了多少
car went where?      ← 你对照：车实际往哪走了
PA5 to clear
```

记满六个方向，就能算出两个宏：

- 如果 **前进让 x 变大** ⇒ `dX>0` 要往**反方向**走 ⇒ `VISION_DX_PLUS_DO_BACK = 1`
- 反之 `= 0`

> 如果出现"日志说 BACK、车却往前走"，那是 `motor.c` 的方向表反了 ——
> 改 `MOTOR_FLIP_FWD`，**不要**动视觉的宏。

### 6.3 目标点标定（换摄像头位置就要重做）

1. 把 K230 在车上装好、举到工作高度
2. 手动把车推到位，让**夹爪正对圆心**
3. 读 OLED 第 2 行的 `X` `Y`（串口也有）
4. 把这两个数抄进 `VISION_TARGET_X/Y`，重编译重烧

### 6.4 OLED 四个画面

| 画面 | 内容 |
|---|---|
| 待机 | `VISION IDLE` / `PB1 SW MODE` / `PA7 JOG PA5 STP` / `DX+FWD DY+RGT` |

### 6.5 症状 → 改哪个宏

| 症状 | 改这里 |
|---|---|
| 走过头、来回摆 | `VISION_STEP_GAIN_PCT` 50→30 |
| 半天不到位 | `VISION_STEP_GAIN_PCT` 50→70 |
| 每步都系统性走多/走少 | `VISION_MM_PER_60PX` 标定不准，重新标 |

## 8. 已知问题 / 技术债

### 8.1 ★ 陀螺仪和 K230 抢 USART2（最大阻塞）

`USART2_IRQHandler` 里同时喂了 **K230 解析器**和 **Gyro_ProcessByte**（角度帧 `55 53 ...`），
因为它们**曾经**都在 USART2 上。现在 USART2 给了 K230，所以：

- ✅ 追圆心**不需要陀螺仪**，不受影响
- ❌ 跑图（ROUTE）和转向（TURN）**要陀螺仪**，现在跑不了

**解法（三选一，都没做）：**

1. 陀螺仪改接 **USART3**（PB10/PB11），把调试打印挤到别处 → 改动最小
2. 陀螺仪接 **USART1**？不行，那是驱动的二进制总线
3. 用**软件串口**（TIM 定时采样）→ 麻烦，不建议

> 建议方案 1。但要注意 `DEBUG_MODE_WIRELESS` 也用 USART3，两者只能选一个。

### 8.2 `LINEAR` 里一个未初始化变量

`vision_link_test()` 的 LINEAR 分支：`uint16_t need;` 在"发散/轮数超限"两条路径下
**没有赋值**，却被最后的 `printf` 读走 → 串口会打一个随机耗时。**不影响动作**（那两个分支不动电机）。
修法：`uint16_t need = 0u;`。

### 8.3 过期标签

`app/servo_test.c` 里屏上写的是 `SERVO PC9 270D` —— 实际驱动的是 **PA1**（PC9 在 C8T6 上不存在）。
只影响显示文字。

### 8.4 废弃但没删的代码

- `DEBUG_MODE_CIRCLE`（旧版 `k230_*` + `circle_track_test`，约 100 行）已被视觉模式取代，可删
- `mingling/` 目录（12 字节旧指令）已废弃
- `app/chassis.c`（速度模式）保留着，视觉现在不用

### 8.5 其它

| 问题 | 说明 |
|---|---|
| `MOTOR_PULSE_PER_360DEG = 17208` | **占位值，还没认真标定**（只影响旋转距离精度） |
| OLED 只能显示 ASCII | `vision_row()` 等只接受 ASCII，塞中文会越界读字库（已有自检脚本防这个） |
| Keil 中文注释 | UTF-8 存盘，Keil 里可能显示乱码，但不影响编译 |
| `.bat` 必须 GBK+CRLF | 用 UTF-8 存会被 cmd 拼行报错 |
| 帧格式两种说法 | F6 有 8 字节/9 字节两版，`chassis_config.h` 里两套都实现了，默认 8 字节 |
