## 2. 正向动作表（6 步，PA8 触发）

| # | 部件 | 动作 | 参数 | 等待 | OLED / 日志 |
|---|---|---|---|---|---|
| 1 | 升降舵机 | 90° → **70°** | 贴近地面 | 800 ms | `GRAB 1/6 LIFT70` |
| 2 | 夹爪舵机 | 65° → **110°** | 夹起物料 | 800 ms | `GRAB 2/6 GRIP110` |
| 3 | **升降电机(6)** | **CCW +1000 脉冲** | 升高 | 到位或 800 ms（见 5.2） | `GRAB 3/6 LIFT+1000` |
| 4 | 升降舵机 | 70° → **170°** | 抬高物料 | 800 ms | `GRAB 4/6 LIFT170` |
| 5 | 旋转舵机 | 240° → **80°** | 转到车上 | 800 ms | `GRAB 5/6 ROT80` |
| 6 | 夹爪舵机 | 110° → **60°** | 放开物料 | 800 ms | `GRAB 6/6 GRIP60` |

### 2.1 第 3 步发出的 13 字节帧（相对位置、立即执行）

```
06  FD  01  00 46  C8  00 00 03 E8  00  00  6B
│   │   │   └─┬─┘  │   └────┬────┘  │   │   └─ 校验
│   │   │     │    │        │       │   └──── 立即执行（不等同步帧）
│   │   │     │    │        │       └──────── 相对位置模式
│   │   │     │    │        └──────────────── 1000 脉冲（0x03E8）
│   │   │     │    └───────────────────────── 加速度 200 档
│   │   │     └────────────────────────────── 速度 70 RPM
│   │   └──────────────────────────────────── CCW = 升高
│   └──────────────────────────────────────── 位置模式 0xFD
└──────────────────────────────────────────── 地址 6
```

- 上电默认**失能**，第一次动之前要 `motor_enable_addr(6)`，否则电机不动。
- 地址 6 不在 `motor_dir_bit()` 的 1~4 极性表里，方向位原样下发，所以 `CCW = 0x01` 就是升高。

## 3. 栈式复位（返回初始状态，准备下一次夹取）

### 3.1 规则

> **每执行一个动作，就把它的"反向动作"压栈；复位时从栈顶逐个弹出执行（后进先出）。**

所以复位顺序 = 正向动作的**完全倒序**：最后做的第一个退，最先做的最后退。这不是手写的表，而是执行时自动生成的，**以后改第 2 节的表，复位顺序自动跟着变**。

### 3.2 每个动作记录什么

| 动作类型 | 压栈内容 |
|---|---|
| 舵机 | `(哪一路舵机, 动作执行前的实际角度)` |
| 步进电机 | `(地址 6, 相反方向, 同样的脉冲数)` |

舵机的"动作前角度"用 `Servo_GetAngle()` 现取，所以微调（`SERVO_TRIM_*`）也会被正确带回。

### 3.3 正向 → 复位的对应关系

| 正向顺序 | 动作 | 栈里存的反向动作 | 复位顺序 |
|---|---|---|---|
| 1 | 升降 90→70 | 升降 → 90 | **R6**（最后退） |
| 2 | 夹爪 65→110 | 夹爪 → 65 | **R5** |
| 3 | 升降电机 CCW +1000 | 升降电机 CW −1000 | **R4** |
| 4 | 升降 70→170 | 升降 → 70 | **R3** |
| 5 | 旋转 240→80 | 旋转 → 240 | **R2** |
| 6 | 夹爪 110→60 | 夹爪 → 110 | **R1**（第一个退） |

### 3.4 实际复位序列（栈顶 → 栈底）

| # | 部件 | 动作 | 等待 |
|---|---|---|---|
| R1 | 夹爪舵机 | 60° → **110°**（空夹爪再合一次，见 3.6） | 800 ms |
| R2 | 旋转舵机 | 80° → **240°**（转回待机位） | 800 ms |
| R3 | 升降舵机 | 170° → **70°** | 800 ms |
| R4 | 升降电机(6) | **CW −1000 脉冲**（降回原位） | 到位或 800 ms |
| R5 | 夹爪舵机 | 110° → **65°** | 800 ms |
| R6 | 升降舵机 | 70° → **90°** | 800 ms |

**结束时四个部件全部回到初始位：旋转 240° / 升降 90° / 夹爪 65° / 升降电机回原位**，与上电安全位一致，可以直接开始下一次夹取。

### 3.5 为什么这个顺序是合理的

- 抬高的机构（升降电机）**在旋转回位之后才下降**：R2 先把臂转回 240° 待机位，R4 再降平台，避免在车/物料上方下降。
- 夹爪回初始位（R5）放在升降电机下降之后，此时臂已离开车体。
- 最后 R6 把升降舵机抬回 90°，机构回到完全张开的待机姿态。

### 3.6 代价 / 可选的简化（需要你定）

纯栈语义会让**空夹爪再合一次**（R1：60°→110°），并且升降舵机走两趟（R3、R6）。若觉得多余：

| 方案 | 复位动作数 | 额外耗时 | 说明 |
|---|---|---|---|
| **A. 纯栈（本文默认）** | 6 | ≈ 4.0 s + 步进 | 完全"倒放"，最符合"先执行什么后恢复什么" |
| B. 去掉 R1 | 5 | ≈ 3.2 s + 步进 | 夹爪从 60° 直接到 65°（合进 R5） |
| C. 按部件去重 | 4 | ≈ 2.4 s + 步进 | 每个部件只记第一次的值，复位顺序 = **最后碰过的先复位**：旋转→240、升降电机−1000、夹爪→65、升降→90 |

## 4. 时序估算

| 阶段 | 内容 | 估算 |
|---|---|---|
| 正向 | 5 次舵机等待（5×800 ms）+ 步进 1000 脉冲 | 4.0 s + 0.3~0.7 s ≈ **4.3~4.7 s** |
| 复位 | 5 次舵机等待（5×800 ms）+ 步进回退 | 4.0 s + 0.3~0.7 s ≈ **4.3~4.7 s** |
| 一轮（PA8 一次） | 正向 + 复位 | ≈ **8.6~9.4 s** |

步进 1000 脉冲的时长取决于速度设定：3200 脉冲/圈 → 1000 脉冲 = 0.3125 圈；30 RPM ≈ 0.63 s，70 RPM ≈ 0.27 s。

## 5. 中止与异常

### 5.1 PA11 中止

- **只在"步与步之间"（等待期间）检查 PA11**，和现在一致。
- **第 3 步（升降电机）执行中不打断**：因为它的反向动作是"−1000 脉冲"，如果走到一半被打断，再退 1000 就会退过头。所以这一步要么等它走完，要么不开始。
- **中止后做什么？** 两个选项，需要你选（问题 Q3）：
  - **选项 1（推荐）**：中止 = 停止正向动作，**立刻执行栈里已经记录的动作的复位**，把机构退回初始位，方便下次继续；
  - **选项 2**：中止 = 原地停住不动，等你手动处理 / 再按一次 PA8 只跑复位。

### 5.2 升降电机的"到位"怎么判断

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A（推荐）** | 轮询 `0x3A` 状态位 bit1，超时兜底 | 不会多等 | 要把 [Serial.c](../Hardware/Serial.c) 的回包帧头地址从 `0x01~0x05` 放宽到 `0x01~0x06`（一行） |
| B | 固定延时 800 ms | 不动串口代码 | 快了慢都要等满 800 ms |

### 5.3 其它异常

- `0x3A` 一直没回包：记一次 `NO ANSWER`，用固定 800 ms 兜底继续，不卡死。
- 步进电机失能 / 堵转：闭环驱动器会自己报错，我们这边只保证帧发出去；如果现场发现丢步，需要按绝对位置或限位重新找零（本次不做）。

## 6. 代码落点（你确认后执行）

1. **[Hardware/Serial.c](../Hardware/Serial.c)**：回包帧头 `0x01~0x05` → `0x01~0x06`（只有选 5.2 方案 A 才需要）。
2. **[app/motor.c](../app/motor.c) / [motor.h](../app/motor.h)**：新增
   ```c
   void motor_move_addr(uint8_t addr, uint8_t dir, uint32_t pulses,
                        uint16_t speed_rpm, uint8_t accel);
   ```
   现有 `motor_jog_addr()` 改成调用它（行为不变），升降电机用它配上自己的速度/加速度。
3. **[User/main.c](../User/main.c)**：
   - 动作表从 5 步扩成 6 步（加第 3 步升降电机），格式扩成"舵机动作 / 电机动作"两种；
   - 加一个 8 深度的撤销栈 + `grab_do()`（执行并压栈）/ `grab_undo_all()`（弹栈复位）；
   - OLED 第 1 行区分阶段：`GRAB 3/6 …` / `BACK 2/6 …`；日志 `[S3] LIFT+1000` / `[R2] ROT -> 240`；
   - 复位完成后回到 `PA8:START` 待机画面。
4. **不动**：地址 5（物料盘）、`chassis.c`、`path_planner.c` 等跑图逻辑。

代码结构示意（只示意，未落地）：

```c
typedef struct {
    uint8_t  is_servo;    /* 1 = 舵机, 0 = 步进电机 */
    ServoId  id;          /* is_servo=1: 哪一路舵机 */
    uint16_t deg;         /* is_servo=1: 目标角度 */
    uint8_t  dir;         /* is_servo=0: 0x01=升高(CCW) / 0x00=下降(CW) */
    uint32_t pulses;      /* is_servo=0: 脉冲数 */

static GrabAction g_undo[8];      /* 撤销栈 */
static uint8_t    g_undo_n;

/* 执行一个动作，并把"反向动作"压栈 */
static uint8_t grab_do(const GrabAction *a);

/* 复位：从栈顶弹出，逐个执行（不再压栈） */
static void grab_undo_all(void);
```

## 7. 需要你确认的问题

1. **Q1 复位要不要真的把空夹爪再合一次？** 纯栈（方案 A）会 `夹爪 60°→110°` 再 `→65°`，多 0.8 s 且对机构没意义。选 A / B / C（见 3.6）。
2. **Q2 升降电机的速度**用多少 RPM？现在 `motor_jog_addr()` 用的是 30 RPM（1000 脉冲约 0.63 s），要更快可以给 70 RPM（约 0.27 s）。
3. **Q3 PA11 中止后**是"立刻栈式复位回初始位"（选项 1），还是"原地停住"（选项 2）？
4. **Q4 复位阶段也要能被 PA11 中止吗？**（建议要，但复位被打断后机构姿态不完整，下次 PA8 直接跑正向可能撞车 —— 需要你确认现场是否接受）
5. **Q5 升降电机的 1000 脉冲**是每次相对累加，还是以"上电位置为 0"的绝对位置？现在是相对 ±1000，闭环驱动器不会累积漂移，但如果中途断电/手动推过，需要重新找零。

## 8. 上板验证清单（改完代码后按这个顺序验）

1. 示波器/舵机测试仪量 PC7/PC8/PC9 三路：20 ms 周期，上电输出 1167 / 981 / 2278 us。
2. 单独测升降电机：`motor_enable_addr(6)` 后发一帧 `06 FD 01 00 46 C8 00 00 03 E8 00 00 6B`，确认**方向是升**、行程 1000 脉冲。
3. 空载跑一次 PA8：确认 6 步顺序、方向、OLED 文案。
4. 空载跑复位：确认 R1~R6 顺序，结束时三个舵机回到 240/90/65，升降电机回到原点。
5. 带物料跑一轮；再跑第二轮，确认起始姿态和第一轮一致（说明复位到位）。
6. 中途按 PA11，确认中止行为符合 Q3 的选择。
