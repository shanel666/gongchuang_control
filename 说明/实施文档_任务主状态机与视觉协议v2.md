**目标**：把现在的"八模式调试台"改造成一个"一键启动、按 `step 0~14` 自动跑完初赛全流程"的比赛程序。

## 4. 串口协议 v2

### 4.1 设计原则

1. **主控是主**：K230 只在收到命令后持续回帧，不主动开口（现有设计，保持）。
2. **一帧一个任务**：不同任务的帧用不同首字母，互不干扰；每类帧独立 `seq`。
3. **必须能表达"3 个色块"**：所以帧长上限要放宽到 48 字节（§4.5）。
4. **数字识别留占位**：`num` 命令和 `N` 帧先定义好，K230 端返回 `NG` 直到实现。
5. **失败要能区分**："没找到" 用 `NG`，"格式/内部错误" 用 `ER<code>` —— 两者处理策略不同（前者重试，后者报警）。

### 4.2 下行命令表（F103 → K230，ASCII + `\r\n`）

| 命令 | 格式 | 含义 | K230 行为 |
|---|---|---|---|
| `qr` | `qr` | 识别二维码任务码 | 找到就一次发 `Q` 帧，然后回 `stop` 状态 |
| `tri` | `tri` | 找转盘上 3 个物料色块 | 持续发 `T` 帧（约 3 Hz） |
| `num` | `num2` | 找数字 `2` 的圆环 | 持续发 `N` 帧 |
| `circle` | `circle` | 找圆（**现有，不变**） | 持续发 `C` 帧 |
| `linear` | `linear` | 三线修偏航（**现有，不变**） | 持续发 `L` 帧 |
| `color` | `color` | 只报一个基准色块（标定用） | 持续发 `G` 帧 |
| `stop` | `stop` | 停 | 回 IDLE，不再回数据 |
| `ping` | `ping` | 心跳 | 回 `P<ms>` |

> `num` 的数字范围 1~5（圆环号）。
> `qr` 是**一次性**任务，K230 拿到结果后自动回 IDLE，避免主控忘了停。

### 4.3 上行帧表（K230 → F103）

| 帧 | 格式 | 长度 | 字段 |
|---|---|---|---|
| 任务码 | `Q<三组>+<三组>+<三组>+<三组>` | 16 | 例 `Q156+123+516+231`（`Q` 只是前缀，载荷正好 15 字符） |
| 三色块 | `T<x1>,<y1>,<c1>,<x2>,<y2>,<c2>,<x3>,<y3>,<c3>` | ≤ 32 | 像素坐标 + 颜色编号 1..6。**顺序按 x 从小到大**，保证主控能区分"来了新组合" |
| 数字框 | `N<x>,<y>` | ≤ 12 | 目标数字的框中心像素坐标 |
| 圆心 | `C<x>,<y>,<r>` | ≤ 16 | **现有，不变** |
| 偏航 | `L<k>,<psi>` | ≤ 16 | **现有，不变** |
| 基准色 | `G<c>` | ≤ 3 | 单色块颜色编号 |
| 未找到 | `NG` | 2 | **现有，不变** |
| 心跳 | `P<ms>` | ≤ 12 | K230 运行毫秒数（看它有没有重启） |
| 错误 | `ER<code>` | ≤ 4 | `1`=内部异常 `2`=缓冲区溢出 `3`=命令不认识 |

**示例（一条完整的三色块帧）**：

```
T118,326,1,264,208,5,420,300,6
   物料1: 像素(118,326) 红色
   物料2: 像素(264,208) 黑色
   物料3: 像素(420,300) 浅蓝
```

主控算三角形中心：`cx = (118+264+420)/3 = 267`，`cy = (326+208+300)/3 = 278`。
**等边三角形的重心 = 外心 = 内心**，所以直接取平均即可，不需要解方程。

### 4.4 帧解析改动（`Serial.c`）

**解析约束**：`K230_ParseLine` 是纯函数，改完必须能通过 `tools/k230_host.py --selftest`（§12 回归门）。

### 4.5 ★ 必须同步改的两个长度

```
Hardware/Serial.c:
    #define USART2_RX_BUF_SIZE  16   →   48
    #define K230_LINE_MAX       16u  →   48u
```

不改的话 `T` 帧会被**整帧丢弃**（超长丢到换行），表现为"一直收不到三色块"。这是最容易踩的坑，排在 P0。

### 4.6 掉线自恢复（沿用现有机制并扩展）

现有 `VISION_RESEND_MAX / VISION_RESEND_GAP` 的逻辑是"静默 2 s 重发一次模式命令"。v2 需要它记住**当前命令 + 参数**：

```c
static char g_last_cmd[8];          /* "tri" / "num2" / "circle" ... */
void k230_start(const char *cmd);   /* 记录 + 发送 */
void k230_poll(void);               /* 主循环每拍调用：静默超时则重发 */
```

### 5.2 `task_qr.py`：二维码

```python
# 伪代码
def run(cmd_done_cb):
    img = sensor.snapshot()
    objs = img.find_qrcodes()
    for o in objs:
        payload = o.payload()          # 期望 "156+123+516+231"
        if is_valid_taskcode(payload):
            uart_send("Q" + payload)
            return DONE                # 一次性任务，直接回 IDLE
    # 没找到：不回 NG，直接下一帧重试（扫码是"盯着看"，NG 会刷屏）
```

**要点**：

| 项 | 做法 |
|---|---|
| 分辨率 | 二维码 80×80 mm，建议取 ROI（画面中心 400×300）提高帧率 |
| 补光 | 赛场灯光不均，开 `Sensor` 的自动增益，别写死曝光 |
| 校验 | `is_valid_taskcode()` 在 K230 上**先做一遍**（四组三位），主控再做一遍。双保险，避免把 `l`/`1`、`O`/`0` 认错 |
| 超时 | 主控侧 20 s 扫不到 → 报故障（§6 step 1） |

### 5.3 `task_tri.py`：三色块 + 三角中心

这是 step 3/9 的核心。**现有脚本是纯灰度**（`GRAYSCALE` + 二值化 `find_blobs`），必须换成 RGB565 + LAB 颜色阈值。

```python
# 每个颜色一组 (L_min,L_max,A_min,A_max,B_min,B_max)，可多组
THRESHOLDS = {
    1: [(30,100, 40, 90, 10, 80)],      # 红  （待标定）
    2: [(60,100, -20, 20, 40, 90)],     # 黄
    3: [(20,70, -20, 30, -80, -20)],    # 蓝
    4: [(20,80, -70, -20, 0, 40)],      # 绿
    5: [(0, 25, -10, 10, -10, 10)],     # 黑 （亮度和低，最易和阴影混）
    6: [(40,90, -30, 10, -50, -10)],    # 浅蓝
}

def run():
    img = sensor.snapshot()
    best = {}                            # color -> best blob
    for c, ths in THRESHOLDS.items():
        for b in img.find_blobs(ths, pixels_threshold=300, area_threshold=300, merge=True):
            # 只用画面下方 2/3（转盘区域），排除背景
            if b.cy() < H * 0.25: continue
            if c not in best or b.pixels() > best[c].pixels():
                best[c] = b
    if len(best) != 3:
        uart_send("NG"); return
    items = sorted(best.items(), key=lambda kv: kv[1].cx())   # 按 x 排序
    uart_send("T%s" % ",".join("%d,%d,%d" % (b.cx(), b.cy(), c) for c, b in items))
```

**必须解决的三个现实问题**：

| 问题 | 对策 |
|---|---|
| **黑色 vs 阴影** | 黑色阈值收紧 + 要求 `b.w()/b.h()` 接近 1（`0.7 < ratio < 1.4`）+ 面积在 400~4000 px。转盘本体颜色要在标定时排除 |
| **浅蓝 vs 蓝** | 两色 LAB 的 B 通道很接近。对策：先按 B 通道分界（例如 `B < -40` = 蓝，`-40..-10` = 浅蓝），标定时把两个样品都放进画面看分界 |
| **色差（规则明确允许）** | 提供 `color_cal.py`：屏上显示每个 blob 的实测 LAB 均值，现场改阈值不用重刷固件 |
| **转盘持续转动 6~10 s/圈** | 不是识别问题而是**时序问题**，见 §6 step 3 |

### 5.4 `task_num.py`：数字识别（★占位）

你选了"先留接口"，所以这里只定义契约，不实现：

```python
def run(wanted):
    # TODO: YOLO / kmodel / 模板匹配，任选其一
    # 要求：返回"数字 == wanted"的那个圆环的框中心
    # 找到 -> uart_send("N%d,%d" % (cx, cy))
```

**三种候选方案的工作量对比**（供你后面决策）：

| 方案 | 工作量 | 抗光照 | 备注 |
|---|---|---|---|
| A. K230 跑 YOLO kmodel | 大（数据集 + 训练 + `nn` 加载框架） | 强 | 现有工程**完全没有** `nn`/kmodel 相关代码，要从零加 |
| B. 传统模板匹配（`find_template`） | 中 | 弱 | 圆环数字只有 1~5，"找 2"其实就是找一横一折的连通域。可以先用几何特征（笔画数/长宽比）粗筛，再模板匹配 |
| C. 不用识别，靠位置反推 | 小 | — | 5 个圆环在 580×150 的长条上**等间距**（环号等距）。粗加工区/暂存区只要用"找圆"找到任意一个环 → 按间距算目标环位置 |

> **我推荐 C + B 组合**：先用"找圆 + 等间距反推"把 step 4/6 跑通（不依赖任何识别），之后有精力再上 A 提高精度。C 能让你在"没有数字识别"的情况下**先跑通全流程**，这对比赛是最重要的。

## 6. 主状态机 step 0~14

### 6.1 状态机骨架

```c
void task_run(void)              /* DEBUG_MODE_TASK 的入口，不返回 */
{
    task_boot();                 /* OLED 自检、使能、举高到安全位 */
    task_wait_one_key();         /* ★ 一键启动：PB1 按住 0.5 s 才算确认 */

    while (1) {
        uint32_t t0 = task_ms();

        switch (g_task.step) {
            case 0:  task_s0_unfold();       break;
            case 1:  task_s1_read_qr();      break;
            /* ... 2..14 ... */
            case TASK_STEP_DONE: task_finish();     break;
            case TASK_STEP_ABORT: task_abort();     break;
        }

        g_task.step_ms += task_ms() - t0;
        task_step_timeout_check();   /* 每步独立超时，超时 → ABORT */
        task_ui_service();           /* OLED 4 行：step / 动作 / 统计 / 故障 */
        k230_poll();                 /* 掉线重发 */
        task_abort_key_check();      /* PA5 随时中止 */
        delay_ms(TASK_LOOP_MS);      /* 10 ms */
    }
}
```

**统一约定**：

- 每个 `task_sN_*()` **只做一小步就返回**，禁止 `while(1)` 等（这是现有视觉闭环的设计哲学，必须保持 —— 否则 K230 掉线、按键、超时全都管不了）。
- 每个函数返回 `TASK_RUNNING / TASK_NEXT / TASK_FAIL`，由 `task_step_done()` 统一推进。
- **所有等待都有上限**，上限到了走"失败处理"，绝不空转。

### 6.2 逐步设计

下表每一行都能直接写成代码。`SLOT` = 车上仓位，`RING` = 圆环号。

---

#### **step 0 — 展开机械臂 + 发扫码任务 + 去扫码位**

| 项 | 内容 |
|---|---|
| 进入 | `arm_home()`：夹爪开（85°）、旋转回抓料位（30°）、升降回 0、分度回 0 仓 |
| 子状态 | `0a` 展开 → `0b` 发 `qr` → `0c` 导航到二维码板前 |
| 动作 | `arm_home()` 约 5 s（升降 0→0 若已在 0 可跳过）；`nav_to_station(ST_QR_BOARD)` |
| 完成判据 | 导航到位（`nav_to_station` 返回 1） |
| 超时 | 展开 15 s、导航 40 s |
| 失败 | 导航失败 → 重试 1 次；再失败 → `ABORT`（规则上没扫码就没成绩，必须报警） |
| 关键约束 | **规则要求"一键启动、只有一次机会"**，所以这一步必须全自动，不能等按键 |

---

#### **step 1 — 读取二维码任务码**

| 项 | 内容 |
|---|---|
| 进入 | `k230_start("qr")`，清 `K230_QrText` |
| 循环 | 每拍检查 `K230_QrSeq` 是否变化 |
| 完成判据 | 收到 `Q` 帧 **且** `taskcode_parse()` 通过 |
| 超时 | 20 s |
| 失败 | ① 收到但校验不过 → 清空重试（最多 5 次）；② 20 s 没有任何 `Q` → 微调位置重扫 1 次（前后各 ±20 mm），仍失败 → 用**默认任务码**继续（见下）|
| 降级 | `#define TASK_DEFAULT_CODE "156+123+516+231"`，屏上显示 `QR FAIL, USE DEFAULT`。**比赛中这可能是唯一能拿分的选择**（总比停在原地 0 分强） |
| 退出 | `k230_start("stop")`；`taskcode_to_book()` 生成账本；OLED 切到任务码页停留 2 s |

> ⚠️ 校验必须严格：四组、每组 3 位、每位 1..6。`Q` 帧只来一次，错了就重扫，**不要"猜"**。

---

#### **step 2 — 去原料区转盘 + 发抓料任务码**

| 项 | 内容 |
|---|---|
| 动作 | `nav_to_station(ST_TURNTABLE)`：走定点 + **粗对位**（用 `tri` 帧的三角中心把车摆到"能看见 3 个物料"的位置） |
| 双阶段定位 | ① 粗：`tri` 帧三角中心 → `vision_circle_issue(cx, cy)` 直到死区；② 精：留给 step 3 逐块做 |
| 完成判据 | 三角中心对准 + 至少一帧 `K230_TriCount == 3` |
| 超时 | 导航 40 s、对位 25 s |
| 失败 | `tri` 一直 `NG` → 说明看不到转盘：车后退 50 mm 重试；再失败 → `ABORT` |
| 退出 | `k230_start("tri")` 保持运行（step 3 要用） |

> **粗对位为什么必要**：转盘 Φ300，3 个物料外接圆直径约 300 mm，摄像头视野有限。先把三角中心拉到夹爪投影点，才能保证 3 个物料都在视野内且机械臂可达。

#### **step 3 — 按色序抓 3 个物料上车（★最难的一步）**

拆成 3 个子循环（每个物料一轮）：

| 子状态 | 动作 | 判据 |
|---|---|---|
| `3a 选目标` | 从账本取 `batch==1, loc==TURNTABLE` 中**任务码色序里最靠前**的那个颜色 → `wanted` | — |
| `3b 精对准` | 在 `T` 帧里找 `color == wanted` 的 blob → `vision_circle_issue(x, y)` | `align_wait_stable(3 帧)` 连续 3 帧在死区 |
| `3c 抓取` | `arm_pick_table(slot)`：合爪 → 升 → 转车上位 → 开爪 → 分度到下一仓 | 动作序列返回 1 |
| `3d 记账` | `book[i].loc = ON_CAR, slot`；`stats.pick_ok++` | — |
| 循环 | 3 个物料抓完 → step 4 | — |

**必须解决：转盘一直在转（6~10 s/圈，转向随机）**

这是本 step 唯一的真正难点。三种策略：

| 策略 | 做法 | 评价 |
|---|---|---|
| A. 追着转 | 估算转盘角速度，让车跟着转 | 底盘做不到连续圆弧，**否决** |
| **B. 等它转到窗口（推荐）** | `T` 帧 3 Hz 持续报坐标，主控**等** `wanted` 色块的坐标进入"工作圆"（以夹爪投影点为心、半径 `TASK_PICK_WINDOW_PX = 90`）且连续 2 帧稳定 → 才开始精对准 | 实现简单、可靠；代价是等待时间（最坏 ~3.3 s/个） |
| C. 抓最近的 | 放弃严格"色序"，谁转到跟前抓谁 | **违反规则**（抓取顺序正确性计分），否决 |

> B 的实现要诚实：`vision_circle_issue` 每次只走 ≤6 mm，转盘边缘线速度约 `π*300/8s ≈ 118 mm/s`，**闭环追不上**。所以 `3b` 必须在"窗口判定通过"后**立刻**执行，且要允许"这一块没抓住就放弃、等下一圈"：
>
> `#define TASK_PICK_MAX_ROUNDS 3`（同一物料最多等 3 圈）

**抓取顺序的严格性**：规则明确写"按任务码规定的顺序依次"。所以 `3a` 必须按 `code.d[0][k]` 严格取色，**不能按颜色分组**。

#### **step 4 — 去粗加工区 + `num` 找 2 + 修车位置**

| 动作 | `nav_to_station(ST_ROUGH)`；到位后 `k230_start("num2")` |
| 目标环号 | `ring = code.d[1][k]`（第 k 个物料的环号）；**不是固定 2**，2 只是例子 |
| 对位 | 收到 `N` 帧 → `vision_circle_issue(nx, ny)`，直到连续 3 帧死区 |
| 超时 | 导航 40 s、对位 20 s |
| 失败 | `N` 一直 `NG` → ① 若已实现方案 C（§5.4），切 `circle` 命令用"找圆 + 等间距反推"兜底；② 都失败 → 前后微调 30 mm 重试；③ 仍失败 → 该物料按"放置失败"记账，继续下一个（**不要 ABORT，能救一个是一个**） |

#### **step 5 — 找圆 + 按码序放料 + 再夹起**

这一步实际是**两个动作**，规则原文是"将第一批三个物料搬运至粗加工区 → 按顺序将已放置在粗加工区的物料搬运到车上 → 运至暂存区"。

拆分为两个 step 内的阶段：

| 阶段 | 动作 |
|---|---|
| `5-PUT` | 对 `k=1..3`：① 车对准 `ring = code.d[1][k]`（`circle` 命令追圆心）② `arm_put_ring(ring)`：旋转到放料位 → 降到放料高度 → 开爪 → 升起 ③ 记账 `loc=ROUGH, ring` |
| `5-PICK` | 对 `k=1..3`（**同一顺序**）：① 对准同一环 ② `arm_pick_rough(ring)`：降到抓料高度 → 合爪 → 升 → 转车上位 → 开爪 → 分度 ③ 记账 `loc=ON_CAR` |

**关键设计：两套视觉目标点**

`vision_circle_issue` 把目标拉到**夹爪投影点** `VISION_TARGET_X/Y = 470/170`。但机械臂"放圆环"时要用**旋转 200° 的姿态**，那时夹爪**不在** 470/170。

所以必须引入"姿态相关的目标点"：

```c
/* app/vision.h 扩展：按机械臂姿态切换视觉目标点 */
#define ARM_POSE_PICK   0u   /* 旋转 30°，对转盘 */
#define ARM_POSE_CAR    1u   /* 旋转 115°，对车身料仓 */
#define ARM_POSE_RING   2u   /* 旋转 200°，对圆环 */

void vision_set_target(uint8_t pose);   /* 改内部 g_target_x/g_target_y */
```

| 姿态 | 标定方法 |
|---|---|
| `PICK` | 现成的 470/170 |
| `RING` | ① 把车摆到圆环前 ② 旋转舵机手动打到 200° ③ 读此时**圆环中心**在画面里的像素 → 抄进 `VISION_TARGET_RING_X/Y` |
| `CAR` | 不需要视觉（放到车上靠机械结构定位），可不标 |

> 这是**必须提前做的标定**，否则"放圆环"会系统性偏移一个固定量。

#### **step 12 — 去暂存区，找"中间那个物料"的颜色**

你的意图：堆叠目标要先确定"同色"。规则原文是"第二批三个物料在暂存区**只能在原来已经放置的物料上进行码垛放置，颜色要一致且第一批物料放置正确**"。

这里有个**歧义必须现场确认**：

| 读法 | 含义 | 影响 |
|---|---|---|
| 读法 A（你的理解） | 只码垛在"第二批某个指定环上的第一批物料"上 | 按环号配对 |
| 读法 B | 第二批每个物料码在"**同一环号**上第一批那个颜色相同的物料"上 | 按环号 + 颜色双条件，若颜色不一致则不能堆 |

**设计取 B**（更保守，也符合"颜色要一致"的字面）。所以 step 12 要做的不是"找中间那个"，而是：

```c
/* 对第二批第 k 个物料：目标环 ring = code.d[1][k]（沿用第二组）
 * 查账本：该 ring 上第一批放的是什么颜色？
 *   同色 → 可以堆（layer=1）
 *   不同色 → 降级：放到该环旁边的空地 / 放弃堆叠，只做到"放下"
 */
```

| 子状态 | 动作 |
|---|---|
| `12a` | 导航到暂存区 |
| `12b` | `circle` 对准目标环（`RING` 姿态目标点） |
| `12c` | 查账本 + 颜色比对 → 决定 `layer` 与是否堆叠 |
| 超时 | 35 s |

#### **step 13 — 堆叠物料**

| 项 | 内容 |
|---|---|
| 高度表 | `LIFT` 绝对脉冲分层：`LAYER0 = ARM_LIFT_RING_LOW`、`LAYER1 = LAYER0 + MAT_H_PULSE`（`MAT_H_PULSE` = 一个物料高度换算的脉冲，**必须实测**） |
| 动作 | 旋转到 `RING` 姿态 → 降到 `LAYER1` 高度 → 微调（可选：再用 `circle` 对一次，找到"底下那个物料的顶面"）→ 开爪 → 升起 |
| 判据 | 规则评分是"是否平稳放置在已有的物料上"。**没有传感器** → 只能靠：① 高度表准 ② 对准准 ③ 慢速下降（`LIFT_MOTOR_SPEED` 降到 20 RPM） |
| 兜底 | 加一个"下压检测"：若给升降发位置命令后 `judge_wait` 很快到位（说明被挡住）→ 视为已接触，立即开爪。现有驱动器不支持力矩检测，**这条路走不通**；只能用"时间 + 高度"盲放 |
| 失败 | 该物料 `stack_fail++`，不 ABORT |

> ⚠️ 这是全流程**风险最高**的一步：没有任何反馈，纯开环。建议先单独做一个 `DEBUG_MODE_STACK` 反复试高度表。

| 退出 | `TASK_STEP_DONE`：OLED 切统计页，`k230_start("stop")`，四轮失能 |

### 6.3 超时汇总表

| step | 超时 | 失败策略 |
|---|---|---|
| 0 | 展开 15 s + 导航 40 s | 导航重试 1 次 → ABORT |
| 1 | 20 s | 重扫 5 次 → 默认码 |
| 2 | 导航 40 s + 对位 25 s | 后退 50 mm 重试 1 次 → ABORT |
| 3 | 每物料 30 s（含转盘等待） | 单物料最多等 3 圈，失败记 `pick_fail`，**继续下一个** |
| 4/6 | 导航 40 s + 对位 20 s | 微调 30 mm 重试 → 该物料按放置失败记账，继续 |
| 5/7 | 每物料 40 s | 同上，继续 |
| 8~11 | 同 2~5 | 同 2~5 |
| 12 | 35 s | 放弃堆叠，只放置 |
| 13 | 每物料 30 s | `stack_fail++`，继续 |
| 14 | 45 s | 超时也认，进 DONE |

**原则**：只有 step 0/2 会 ABORT（前面就输光了），中间步骤全部"降级继续"。这样即使中途出错也能拿部分分。

## 7. 视觉 ↔ 机械臂联动仲裁（`align.c`）

现在 `vision` 和 `grab` 互不认识（README §9 自己列的"第二优先"）。补一个薄层：

```c
typedef enum { ALIGN_WAIT, ALIGN_STABLE, ALIGN_TIMEOUT, ALIGN_LOST } AlignResult;

/* 反复"取最新帧 → vision_circle_issue"直到连续 stable_frames 帧死区。
 * max_ms 到了返回 ALIGN_TIMEOUT；连续 lost_frames 帧 NG 返回 ALIGN_LOST。
 * 动作执行期间必须调用 align_pause()，避免车和机械臂同时动把 K230 晃掉线。 */
AlignResult align_to_point(AlignSource src, uint16_t max_ms, uint8_t stable_frames);
```

`AlignSource` 决定从哪取坐标：

```c
typedef enum {
    ALIGN_SRC_CIRCLE,   /* K230_Cx/Cy + K230_CircleSeq */
    ALIGN_SRC_TRI,      /* K230_TriX/Y 里指定 index */
    ALIGN_SRC_TRI_MID,  /* 三角中心（自己算） */
    ALIGN_SRC_NUM,      /* K230_NumX/Y + K230_NumSeq */
} AlignSource;
```

**三档稳定判据**（这是"识别抖一下就去抓"的防线）：

| 场景 | `stable_frames` | 理由 |
|---|---|---|
| 对圆环（`circle`） | 3 | 圆环稳定，3 帧足够 |
| 对数字框（`num`） | 4 | 数字识别抖动大 |
| 对转盘物料（`tri`） | 2 | 转盘在动，不能等太久 |

## 8. 动作层参数化（`arm.c`）

### 8.1 现在的问题

`k_grab_steps[]` 是 `const` 常量表，只有**一个**固定序列（抓 → 升 2000 → 转 115° → 开爪 → 倒序复位）。它做不到：

- 抓到第 2/3 个物料时分度到 `SLOT_2/SLOT_3`
- 放到圆环（需要旋转 200° 姿态 + 不同下降高度）
- 从圆环/车上取料
- 码垛分层

### 8.2 改成"原语 + 复合序列"

```c
/* 单个原语：一次执行 + 等到位，返回 1 = 到位，0 = 被 PA5 中止 */
uint8_t arm_grip(uint16_t deg);          /* 夹爪 */
uint8_t arm_rot(uint16_t deg);           /* 旋转 */
uint8_t arm_lift(uint32_t abs_pulses);   /* 升降（绝对） */
uint8_t arm_index(uint8_t slot);         /* 分度到 slot：算角度差 → material_motor_move → 等到位 */
```

```c
/* 复合序列 */
uint8_t arm_home(void);                       /* 全部回安全位 */
uint8_t arm_pick_table(uint8_t slot);         /* 转盘抓一个 → 放车上 slot → 分度到 slot+1 */
uint8_t arm_put_ring(uint8_t ring, uint8_t layer);  /* 放到圆环（layer 决定高度） */
uint8_t arm_pick_rough(uint8_t ring);         /* 从粗加工区取回 → 放车上 */
uint8_t arm_put_temp(uint8_t ring, uint8_t layer);
```

### 8.3 关键时序表（写在 `arm.h`，现场可调）

```c
#define ARM_GRIP_OPEN       85u
#define ARM_GRIP_CLOSE      115u
#define ARM_ROT_PICK        30u
#define ARM_ROT_CAR         115u
#define ARM_ROT_RING        200u    /* ★ 未实测，必须现场标 */
#define ARM_LIFT_HOME       0u
#define ARM_LIFT_TRAVEL     2000u   /* 转移高度（现有值） */
#define ARM_LIFT_RING_LOW   1200u   /* ★ 放到圆环的高度，待实测 */
#define ARM_LIFT_ROUGH_LOW  1000u   /* ★ 从粗加工区取料的高度，待实测 */

#define ARM_SERVO_SETTLE_MS   800u   /* 现有值 */
#define ARM_LIFT_MS_PER_1000P 550u   /* 现有值，跟 LIFT_MOTOR_SPEED 绑定 */
```

### 8.4 `arm_pick_table(slot)` 展开（伪代码）

```
arm_rot(ARM_ROT_PICK)                  /* 30° */
arm_grip(ARM_GRIP_OPEN)                /* 85° */
arm_lift(ARM_LIFT_ROUGH_LOW)           /* 降到抓取高度 */
arm_grip(ARM_GRIP_CLOSE)               /* 115° 夹紧 */
arm_lift(ARM_LIFT_TRAVEL)              /* 升过车身高 */
arm_rot(ARM_ROT_CAR)                   /* 115° 转到车上 */
arm_grip(ARM_GRIP_OPEN)                /* 松开，物料落到 slot */

```

## 9. 导航与坐标（`nav.c`）

### 9.1 现状的问题

现有 `path_planner.c` 是**旧场地**的 5×5 栅格 + Dijkstra + 编译期障碍物（`path_config.h`），而今年的场地是"启停区 + Φ300 转盘 + 两条 580×150 长条"。**继续用栅格反而是负担。**

### 9.2 改成"站点表 + 直连"

```c
typedef enum {
    ST_HOME_A = 0,   /* 启停区 A（抽签） */
    ST_HOME_B,       /* 启停区 B（抽签） */
    ST_QR_BOARD,     /* 二维码板前 */
    ST_TURNTABLE,    /* 原料区转盘前 */
    ST_ROUGH_L,      /* 粗加工区左端 */
    ST_ROUGH_R,      /* 粗加工区右端 */
    ST_TEMP_L,       /* 暂存区左端 */
    ST_TEMP_R,       /* 暂存区右端 */
    ST_COUNT
} Station;

typedef struct {
    uint16_t x, y;       /* 相对场地的 mm 坐标，现场输入 */
    uint8_t  heading;    /* 到位后车头朝向 1=北 2=西 3=南 4=东 */
} StationPos;

extern StationPos g_station[ST_COUNT];
```

`nav_to_station(id)` = ① 算朝 `heading` 需要的转角 ② 到位（`go_to` 或直走）③ 视觉微调（由调用方做）。

> **为什么不再用 Dijkstra**：初赛场地没有中间障碍，区域是"启停区 → 转盘 → 长条"的星形拓扑，直连 4~6 段就够。Dijkstra 留给决赛场地变化时再用（代码不用删，`#if NAV_USE_PLANNER` 包起来）。

### 9.3 运行时输入发车位置和障碍物

你原话："调试把发车位置和障碍物坐标输入进代码"。**建议做成串口输入**，理由：比赛现场抽签在调试结束前 1 分钟，重编译+烧写来不及。

```c
/* 在 DEBUG_MODE_TASK 的启动等待阶段（还没开始跑）接收配置行：
 *   "ST 3 1200 800 1"   → 设置站点 3 = (1200, 800) 朝向 1
 *   "START 2"           → 用 ST_HOME_B 作为发车位置
 *   "OBS 675 1725"      → 加一个障碍物（可选）
 *   "SAVE"              → 写入 Flash（★ 可选，见下）
 *   "RUN"               → 开始跑
 */
```

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 串口命令 + RAM | 最简单，改一次不用重烧 | 断电丢失 |
| **B. 串口命令 + 写 Flash 末页** | 断电保留，场地点一次就行 | 需要 Flash 读写（F103C8 64 KB，末页 1 KB 够用），要写 `Flash.c` |
| C. 保持编译期宏 | 零工作量 | 现场来不及 |

**建议先 A，跑通后再加 B。** 20 KB RAM 里放 8 个站点 = 8×5 = 40 字节，毫无压力。

### 9.4 定点停靠的三个层次

| 层次 | 手段 | 精度 |
|---|---|---|
| L1 粗停 | `go_to` / 直走 + `judge_wait` | ±10 mm（脉冲标定误差 + 打滑） |
| L2 视觉二次修正 | `align_to_point()` | ±3 mm（`VISION_DEADBAND_PX 15` ≈ 9 mm，可收紧到 8 px ≈ 5 mm） |
| L3 姿态修正 | `vision_yaw_issue()`（`linear` 命令） | ±0.6° |

**每个需要精度的步骤（step 3/4/5/6/7/11/12/13）都必须走 L2**，L1 只负责"别撞到东西"。

## 13. 风险与备案

| # | 风险 | 影响 | 备案 |
|---|---|---|---|
| R1 | **转盘一直在转**（6~10 s/圈，转向随机） | step 3 抓不到 | 窗口等待策略（§6 step 3 策略 B）+ `TASK_PICK_MAX_ROUNDS 3` |
| R2 | **K230 电源被拉塌重启** | 全流程崩 | 沿用现有"降速 + 分步 + 每步 150 ms 停顿"；`k230_poll` 自动重发命令；`P<ms>` 帧能看出重启 |
| R3 | **数字识别（P4）** | step 4/6 卡死 | **先做方案 C**（找圆 + 等间距反推），完全绕开识别；`num` 接口留着 |
| R4 | **第四组三位数的含义** | 第二批放错环 | 规则原文只说"第二批物料在**粗加工区**的放置位置"，没写暂存区。**建议暂存区沿用第二组**，并在赛前向裁判确认。代码里用 `#define TASK_TEMP_USE_D1 1` 一键切换 |
| R5 | **陀螺仪和 K230 抢 USART2** | 长距离定向不可用 | ① 区域间靠"里程计 + 视觉二次修正"，不用陀螺仪（现方案）；② 或把陀螺仪挪 USART3（就放弃无线调试）；③ 初赛场地小，**建议不做陀螺仪**，省掉这个冲突 |
| R6 | **码垛纯开环** | 堆不稳丢分 | 降低 `LIFT_MOTOR_SPEED` 到 20 RPM；单独做 `DEBUG_MODE_STACK` 反复试；`stack_ok/fail` 记账便于分析 |
| R7 | **20 KB RAM** | 溢出 | 新增结构体总计 < 200 字节，无压力；但注意 `sprintf` 栈开销，`act[]` 缓冲别超过 32 字节 |
| R8 | **帧长从 16 放宽到 48** | 老解析回归 | `tools/k230_host.py --selftest` 必须覆盖：超长丢弃、白名单过滤、短帧、乱序 |
| R9 | **`MOTOR_PULSE_PER_360DEG` 未标定** | 所有转角系统性偏 | 排在标定表第 1 位，**必须在 P4 之前做完** |
